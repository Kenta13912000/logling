# Units：日記で経験値（diary-exp）

## 全体像

```
U-3 ホーム画面（画面の組み立て・ブラウザ保存）
 ├─ U-1 キャラクター（名前・経験値・レベル）
 └─ U-2 日記（今日の日記・朝 4 時の区切り）
```

- U-1 と U-2 はお互いを知らない。日記を保存したらキャラクターに経験値を入れる、というつなぎは U-3 が受け持つ
- 複数の Unit や今後の機能（`streak`・`diary-history` など）で使う処理は `src/lib/` に置く（例：ブラウザ内への保存、朝 4 時で区切った日付）

## U-1：キャラクター（`src/features/character/`）

- 含む Story：S-1, S-3, S-4
- 依存：なし
- 受け持つこと：名前の検証、経験値の加算とレベルの計算、名前の入力欄・レベルと経験値の表示・レベルアップのお知らせの部品

### Bolt 計画

- Bolt-1：名前の検証、経験値とレベルの計算、キャラクターの表示部品（AC-1, AC-2, AC-3, AC-4, AC-9, AC-10, AC-11, AC-12, AC-13）
- Bolt-5：名前を決める前の確認（AC-23）。Bolt-3 のあとに追加。Bolt-4 の前に行う

### 設計（⑤で追記）

#### 経験値とレベルのきまり

| 項目                     | 値                                            | 例                                    |
| ------------------------ | --------------------------------------------- | ------------------------------------- |
| 日記 1 件の経験値        | 10                                            |                                       |
| 次のレベルまでに必要な量 | 20 + 10 × 今のレベル                          | Lv1→2 は 30、Lv2→3 は 40、Lv3→4 は 50 |
| レベルの上限             | なし                                          |                                       |
| 毎日書いた場合の目安     | Lv2 まで 3 日、Lv3 まで 7 日、Lv10 まで 63 日 |                                       |

#### データの形

```ts
type Character = {
  name: string; // 前後の空白を取り除いた 1〜10 文字
  totalExp: number; // これまでにためた経験値の合計（0 以上の整数）
};
```

- **保存するのは名前と経験値の合計だけ**にする。レベル・今のレベル内の経験値・次のレベルまでの残りは、合計から毎回計算する
  - 理由：レベルと経験値を別々に持つと、食い違った状態（例：Lv2 なのに経験値の合計が 0）が起こりうる。合計 1 つから計算すれば、必ずつじつまが合う
  - 経験値の数を後から変えても、保存済みのデータを書き換えずに済む

#### 関数（ロジック。画面に依存しない）

| 関数                         | 入力                 | 出力                                                                 | 対象の AC    |
| ---------------------------- | -------------------- | -------------------------------------------------------------------- | ------------ |
| `validateName(input)`        | 入力された名前       | 成功：前後の空白を除いた名前／失敗：理由（`empty` または `tooLong`） | AC-2〜AC-4   |
| `createCharacter(name)`      | 検証済みの名前       | 経験値 0 のキャラクター                                              | AC-2         |
| `getLevelInfo(totalExp)`     | 経験値の合計         | レベル・今のレベル内の経験値・次のレベルまでに必要な量・残り         | AC-10, AC-11 |
| `gainExp(character, amount)` | キャラクター・経験値 | 経験値を足したキャラクター・レベルが上がったか・上がった後のレベル   | AC-9, AC-11  |

- 名前の文字数は、見た目の 1 文字を 1 と数える（絵文字や「が」のような合成文字も 1 文字）。ブラウザ標準の `Intl.Segmenter` を使う
- 関数は元のデータを書き換えず、新しいデータを返す（テストしやすく、画面の更新とも相性がよい）

#### 画面の部品（React コンポーネント）

| 部品              | 表示するもの                                                 | 受け取るもの                       | 対象の AC    |
| ----------------- | ------------------------------------------------------------ | ---------------------------------- | ------------ |
| `NameForm`        | 🐣・あいさつ・名前の入力欄・エラー・「この名前にする」ボタン | 名前が決まったときに呼ぶ関数       | AC-1〜AC-4   |

#### ⑥ で書くテスト（例）

- `getLevelInfo`：合計 0 → Lv1・0/30／合計 29 → Lv1／合計 30 → Lv2・0/40／合計 70 → Lv3

#### Bolt-5：名前を決める前の確認（⑤で追記）

`NameForm` の中に「入力」と「確認」の 2 つの段階を持たせる。画面は切り替えず、同じ場所で表示を入れ替える。

| 段階 | 表示するもの                                                                                   | 操作                                                                                                  |
| ---- | ---------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| 入力 | これまでどおり（あいさつ・名前の入力欄・エラー・「この名前にする」）                           | 「この名前にする」：名前を検証し、問題がなければ「確認」へ。問題があればエラー（AC-3, AC-4）          |
| 確認 | 🐣・「『<名前>』でいい？」・「名前はあとから変えられないよ」・「これにする」・「えらびなおす」 | 「これにする」：名前を決める（`onSubmit` を呼ぶ）／「えらびなおす」：入力に戻る（入力した名前は残す） |

- `NameForm` が外に知らせるのは、これまでどおり「名前が決まったとき」の `onSubmit` だけ。確認の段階は部品の中だけで扱うので、U-3（`Home`）の作りは変わらない
- 名前の検証は「この名前にする」を押したときに行う。確認の段階に進むのは、検証に通った名前だけ
- 確認に切り替わったら、確認の文にフォーカスを移す（読み上げ機能で切り替わりが伝わるように）。「えらびなおす」で戻ったら、入力欄にフォーカスを戻す
- 名前の前後の空白は、確認の時点で取り除いた形（実際に保存される名前）で見せる

**テストへの影響（⑥）**

- `NameForm.test.tsx`：AC-23 のテストを追加する。AC-2 のテストは「この名前にする」→「これにする」の 2 段階で名前が渡る形に直す
- `Home.test.tsx`：名前を付ける操作がある 2 件（AC-5, AC-17）に「これにする」を押す手順を加える
- 仕様の追加に合わせて既存のテストを直すため、テストの期待する動きが変わるのは AC-2（確認を経てから名前が決まる）だけ

## U-2：日記（`src/features/diary/`）

- 含む Story：S-2, S-5
- 依存：なし

### Bolt 計画

- Bolt-2：本文の検証、朝 4 時の区切り、日記の入力と表示の部品（AC-5, AC-7, AC-8, AC-14, AC-15）

### 設計（⑤で追記）

#### データの形

```ts
type DiaryEntry = {
  date: string; // 日記の日付（朝 4 時区切り）。"2026-10-28" の形
  body: string; // 前後の空白・改行を取り除いた本文（1〜2000 文字）
  createdAt: string; // 保存した時刻（ISO 8601 形式）
};
```

- 「何日の日記か」は保存した時刻からではなく、**朝 4 時で区切った日付 `date`** で決める。1 日 1 件の判定（Bolt-3）も `date` で行う
- 保存した時刻 `createdAt` も残す。今後の `diary-history` や `streak` で使えるようにするため

#### 朝 4 時の区切りと日付の表示（`src/lib/` に置く）

| 関数                    | 入力       | 出力                                   | 対象の AC |
| ----------------------- | ---------- | -------------------------------------- | --------- |
| `getDiaryDate(now)`     | 今の時刻   | 日記の日付（`"2026-10-28"`）           | AC-15     |
| `formatDiaryDate(date)` | 日記の日付 | 表示用の文字（`2026年10月28日（水）`） | AC-5      |

- 端末の時刻（ローカル時刻）で計算する。4 時より前なら前の日の日付にする
  - 例：28 日 23:00 → 28 日／29 日 3:59 → 28 日／29 日 4:00 → 29 日
- `streak` や `diary-history` でも使うため、Unit ではなく共有の `src/lib/diary-date.ts` に置く
- 曜日は「日月火水木金土」から選び、かっこは全角にする（ブラウザの日付の書式は半角になるため使わない）

#### 本文の検証（U-2）

| 関数                  | 入力         | 出力                                                                               | 対象の AC  |
| --------------------- | ------------ | ---------------------------------------------------------------------------------- | ---------- |
| `validateBody(input)` | 入力した本文 | 成功：前後の空白・改行を除いた本文／失敗：理由（`empty` または `tooLong`）と文字数 | AC-7, AC-8 |

- 前後の空白・改行だけを取り除き、途中の改行はそのまま残す
- 文字数は取り除いた後の本文で数え、見た目の 1 文字を 1 とする。名前と同じ数え方なので、Bolt-1 の `name.ts` にある数え方を共有の `src/lib/text.ts`（`countCharacters`）に移して両方で使う

## U-3：ホーム画面（`src/features/home/`）

- 含む Story：S-6, S-7
- 依存：U-1, U-2
- 受け持つこと：状態に応じた画面の切り替え（名前がない → 名前の入力／今日の日記がない → 入力欄／書いた → 今日の日記）、保存 → 経験値 → お知らせのつなぎ、ブラウザ内への保存と読み込み、スマホ向けの見た目、`src/app/page.tsx` からの呼び出し

### Bolt 計画

- Bolt-3：画面の組み立てとブラウザ内への保存（AC-1, AC-6, AC-9, AC-11, AC-13, AC-14, AC-16, AC-17, AC-21, AC-22）
- Bolt-4：スマホ幅での表示、ページの言語とタイトル、名前を付けてから保存するまでの E2E テスト（AC-18, AC-19, AC-20）

### 設計（⑤で追記）

#### 保存の形（ブラウザの localStorage。選定理由は [ADR-0002](../../adr/0002-browser-storage.md)）

```ts
// キー "logling:v1" に JSON で 1 つだけ保存する
type SaveData = {
  version: 1; // 形を変えるときの目印（account-sync での引き継ぎにも使う）
  character: Character | null; // まだ名前を付けていなければ null
  entries: DiaryEntry[]; // 書いた日記（古い順）
};
```

- 名前を付けたとき・日記を保存したときに、`SaveData` 全体を書き込む
- 読み込むときは、JSON として読めるかと、形（型）が合っているかを確かめる
  - キーがない → 初めて開いた状態（キャラクターなし・日記なし）
  - 読めない・形が合わない → 「壊れている」状態（AC-21）
- 壊れたデータで「はじめからにする」を選んだときは、元のデータを `logling:v1:broken:<日時>` という別のキーに移してから、初めて開いた状態に戻す。壊れたデータは消さない

#### 画面の状態と切り替え

| 状態                                 | 表示するもの                         | 対象の AC |
| ------------------------------------ | ------------------------------------ | --------- |
| 読み込み中（サーバーでの描画時）     | アプリ名だけ                         |           |
| 保存データが壊れている               | お知らせと「はじめからにする」ボタン | AC-21     |
| キャラクターがいない                 | `NameForm`                           | AC-1      |
| キャラクターがいて、今日の日記がない | `CharacterStatus` と `DiaryEditor`   | AC-5      |
| キャラクターがいて、今日の日記がある | `CharacterStatus` と `TodayEntry`    | AC-14     |

- 画面の上には、どの状態でもアプリ名「logling」を見出し（`h1`）として表示する
- 「今日」の日付は、開いたときと、保存するとき、画面に戻ってきたとき（タブを切り替えて戻ったときなど）に `getDiaryDate` で計算し直す。開いたまま朝 4 時を過ぎても、次の日の日記を書けるようにするため

#### 日記を保存したときの流れ

1. 保存する時刻で「今日」の日付を計算し直す
2. `gainExp` で経験値を 10 足し、レベルが上がったかを受け取る
3. 日記とキャラクターを `SaveData` にまとめて書き込む
4. 書き込みに成功したら：画面を「今日の日記」に切り替え、「✨ +10 経験値！」を出す。レベルが上がったときは、続けて `LevelUpDialog` を出す（AC-9, AC-11, AC-12, AC-13, AC-14）
5. 書き込みに失敗したら：「保存できなかった…少し時間をおいて、もう一度ためしてね」を出す。画面は入力欄のままで、書いた文章は残り、経験値も入らない（AC-22）

#### 責務の置き場所

| ファイル                                 | 受け持つこと                                                                                      |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------- |
| `src/lib/storage.ts`                     | localStorage の読み書き。ブラウザが保存を禁止しているときなどの失敗を、例外ではなく結果として返す |
| `src/features/home/save-data.ts`         | `SaveData` の型・キー・読み込み時の形のチェック・控えを残してやり直す処理                         |
| `src/features/home/useSaveData.ts`       | 保存データを画面で使うための React のフック（読み込み中・壊れている・通常の状態を返す）           |
| `src/features/home/Home.tsx`             | 状態に応じた画面の切り替えと、保存 → 経験値 → お知らせのつなぎ。`'use client'` を付ける入口       |
| `src/features/home/BrokenDataNotice.tsx` | 保存データが壊れているときのお知らせ                                                              |
| `src/app/page.tsx`                       | `Home` を表示するだけ（ロジックは置かない）                                                       |

- 「今日」の日付は `src/features/home/useToday.ts`（`useSyncExternalStore`）で扱う。サーバーでの事前描画で今の時刻を読むと Next.js 16 のビルドが止まるため、時刻はブラウザでだけ読む（⑦ で追加）
- 読み込みには React の `useSyncExternalStore` を使う。サーバーでの描画では「読み込み中」を返し、ブラウザで localStorage を読んでから本来の画面を出す。サーバーとブラウザで表示が食い違うエラーを防ぐため
- localStorage は外部と通信しない。アプリの中で `fetch` など外部への送信は行わない（AC-17）

#### ⑥ で書くテスト（例）

- `save-data`：キーがない → 初めての状態／正しい JSON → そのまま読める／壊れた JSON・形が違う → 壊れている／やり直し → 控えのキーに元のデータが残り、本来のキーは初めての状態
- `storage`：保存が禁止されている（例外が出る）ときに失敗を結果として返す
- `Home`：初めて開く → 名前の入力欄（AC-1）／名前を付ける → 日記の入力欄（AC-5）／保存 → 今日の日記に切り替わり、経験値が 10 増え、localStorage に残る（AC-6, AC-9, AC-14, AC-16）／経験値 20 の状態で保存 → レベルアップのお知らせ（AC-11, AC-12）・経験値 0 からでは出ない（AC-13）／開き直しても同じ表示（AC-16）／保存の失敗 → メッセージ・文章が残る・経験値が増えない（AC-22）／壊れたデータ → お知らせ・やり直すと控えが残る（AC-21）／一連の操作で `fetch` が呼ばれない（AC-17）
- 既存の `src/app/page.test.tsx`（見出しが表示される）も、そのまま通ること
