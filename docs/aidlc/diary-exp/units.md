# Units：日記で経験値（diary-exp）

## 全体像

```
U-3 ホーム画面（画面の組み立て・ブラウザ保存）
 ├─ U-1 キャラクター（名前・経験値・レベル）
 └─ U-2 日記（今日の日記・朝 4 時の区切り）
```

- U-1 と U-2 はお互いを知らない。日記を保存したらキャラクターに経験値を入れる、というつなぎは U-3 が受け持つ
- 複数の Unit や今後の機能（`streak`・`diary-history` など）で使う処理は `src/lib/` に置く（例：ブラウザ内への保存、朝 4 時で区切った日付）

## U-1：キャラクター（`src/features/character/`）

- 含む Story：S-1, S-3, S-4
- 依存：なし
- 受け持つこと：名前の検証、経験値の加算とレベルの計算、名前の入力欄・レベルと経験値の表示・レベルアップのお知らせの部品

### Bolt 計画

- Bolt-1：名前の検証、経験値とレベルの計算、キャラクターの表示部品（AC-1, AC-2, AC-3, AC-4, AC-9, AC-10, AC-11, AC-12, AC-13）

### 設計（⑤で追記）

#### 経験値とレベルのきまり

| 項目                     | 値                                            | 例                                    |
| ------------------------ | --------------------------------------------- | ------------------------------------- |
| 日記 1 件の経験値        | 10                                            |                                       |
| 次のレベルまでに必要な量 | 20 + 10 × 今のレベル                          | Lv1→2 は 30、Lv2→3 は 40、Lv3→4 は 50 |
| レベルの上限             | なし                                          |                                       |
| 毎日書いた場合の目安     | Lv2 まで 3 日、Lv3 まで 7 日、Lv10 まで 63 日 |                                       |

#### データの形

```ts
type Character = {
  name: string; // 前後の空白を取り除いた 1〜10 文字
  totalExp: number; // これまでにためた経験値の合計（0 以上の整数）
};
```

- **保存するのは名前と経験値の合計だけ**にする。レベル・今のレベル内の経験値・次のレベルまでの残りは、合計から毎回計算する
  - 理由：レベルと経験値を別々に持つと、食い違った状態（例：Lv2 なのに経験値の合計が 0）が起こりうる。合計 1 つから計算すれば、必ずつじつまが合う
  - 経験値の数を後から変えても、保存済みのデータを書き換えずに済む

#### 関数（ロジック。画面に依存しない）

| 関数                         | 入力                 | 出力                                                                 | 対象の AC    |
| ---------------------------- | -------------------- | -------------------------------------------------------------------- | ------------ |
| `validateName(input)`        | 入力された名前       | 成功：前後の空白を除いた名前／失敗：理由（`empty` または `tooLong`） | AC-2〜AC-4   |
| `createCharacter(name)`      | 検証済みの名前       | 経験値 0 のキャラクター                                              | AC-2         |
| `getLevelInfo(totalExp)`     | 経験値の合計         | レベル・今のレベル内の経験値・次のレベルまでに必要な量・残り         | AC-10, AC-11 |
| `gainExp(character, amount)` | キャラクター・経験値 | 経験値を足したキャラクター・レベルが上がったか・上がった後のレベル   | AC-9, AC-11  |

- 名前の文字数は、見た目の 1 文字を 1 と数える（絵文字や「が」のような合成文字も 1 文字）。ブラウザ標準の `Intl.Segmenter` を使う
- 関数は元のデータを書き換えず、新しいデータを返す（テストしやすく、画面の更新とも相性がよい）

#### 画面の部品（React コンポーネント）

| 部品              | 表示するもの                                                 | 受け取るもの                       | 対象の AC    |
| ----------------- | ------------------------------------------------------------ | ---------------------------------- | ------------ |
| `NameForm`        | 🐣・あいさつ・名前の入力欄・エラー・「この名前にする」ボタン | 名前が決まったときに呼ぶ関数       | AC-1〜AC-4   |
| `CharacterStatus` | 🐣・名前・レベル・経験値のバー・次のレベルまでの残り         | キャラクター                       | AC-10        |
| `LevelUpDialog`   | 🎉・「<名前> が レベル <N> になった！」・「とじる」          | 名前・レベル・閉じたときに呼ぶ関数 | AC-12, AC-13 |
| `ExpGainToast`    | 「✨ +10 経験値！」（2〜3 秒で消える）                       | 増えた経験値                       | AC-9         |

- 部品は**表示と入力の受け取りだけ**を受け持ち、データの保存や「いつ表示するか」の判断は U-3（Bolt-3）が受け持つ
- `LevelUpDialog` は HTML 標準の `<dialog>` を使う。開いたときに「とじる」にフォーカスが移り、閉じると元の場所に戻る動きをブラウザに任せられるため
- 文言はモック（[mockup.md](mockup.md)）のとおり。エラーの文言は部品の中で、理由（`empty`・`tooLong`）から決める

#### ファイルの置き場所

```
src/features/character/
├─ character.ts              # 型・経験値の定数・getLevelInfo・gainExp・createCharacter
├─ character.test.ts
├─ name.ts                   # validateName
├─ name.test.ts
├─ NameForm.tsx / NameForm.test.tsx
├─ CharacterStatus.tsx / CharacterStatus.test.tsx
├─ LevelUpDialog.tsx / LevelUpDialog.test.tsx
└─ ExpGainToast.tsx / ExpGainToast.test.tsx
```

#### ⑥ で書くテスト（例）

- `getLevelInfo`：合計 0 → Lv1・0/30／合計 29 → Lv1／合計 30 → Lv2・0/40／合計 70 → Lv3
- `gainExp`：合計 20 に 10 足す → Lv2 に上がった（leveledUp: true）／合計 0 に 10 足す → 上がらない
- `validateName`：「ぴよ」→ 成功／「　ぴよ　」→「ぴよ」／空・空白だけ → `empty`／11 文字 → `tooLong`／絵文字を含む 10 文字 → 成功
- 部品：エラー文言の表示、レベルと残りの表示、お知らせの文言と「とじる」で閉じる動き

#### ADR

この Bolt では、技術の選定を伴う判断はないため ADR は作らない（経験値のきまりは本ファイルに記録）。ブラウザ内への保存の方針は Bolt-3 で ADR-0002 として残す。

## U-2：日記（`src/features/diary/`）

- 含む Story：S-2, S-5
- 依存：なし
- 受け持つこと：本文の検証、朝 4 時で区切った「日記の日付」の計算、日記の入力欄・今日の日記の表示の部品

### Bolt 計画

- Bolt-2：本文の検証、朝 4 時の区切り、日記の入力と表示の部品（AC-5, AC-7, AC-8, AC-14, AC-15）

### 設計（⑤で追記）

#### データの形

```ts
type DiaryEntry = {
  date: string; // 日記の日付（朝 4 時区切り）。"2026-10-28" の形
  body: string; // 前後の空白・改行を取り除いた本文（1〜2000 文字）
  createdAt: string; // 保存した時刻（ISO 8601 形式）
};
```

- 「何日の日記か」は保存した時刻からではなく、**朝 4 時で区切った日付 `date`** で決める。1 日 1 件の判定（Bolt-3）も `date` で行う
- 保存した時刻 `createdAt` も残す。今後の `diary-history` や `streak` で使えるようにするため

#### 朝 4 時の区切りと日付の表示（`src/lib/` に置く）

| 関数                    | 入力       | 出力                                   | 対象の AC |
| ----------------------- | ---------- | -------------------------------------- | --------- |
| `getDiaryDate(now)`     | 今の時刻   | 日記の日付（`"2026-10-28"`）           | AC-15     |
| `formatDiaryDate(date)` | 日記の日付 | 表示用の文字（`2026年10月28日（水）`） | AC-5      |

- 端末の時刻（ローカル時刻）で計算する。4 時より前なら前の日の日付にする
  - 例：28 日 23:00 → 28 日／29 日 3:59 → 28 日／29 日 4:00 → 29 日
- `streak` や `diary-history` でも使うため、Unit ではなく共有の `src/lib/diary-date.ts` に置く
- 曜日は「日月火水木金土」から選び、かっこは全角にする（ブラウザの日付の書式は半角になるため使わない）

#### 本文の検証（U-2）

| 関数                  | 入力         | 出力                                                                               | 対象の AC  |
| --------------------- | ------------ | ---------------------------------------------------------------------------------- | ---------- |
| `validateBody(input)` | 入力した本文 | 成功：前後の空白・改行を除いた本文／失敗：理由（`empty` または `tooLong`）と文字数 | AC-7, AC-8 |

- 前後の空白・改行だけを取り除き、途中の改行はそのまま残す
- 文字数は取り除いた後の本文で数え、見た目の 1 文字を 1 とする。名前と同じ数え方なので、Bolt-1 の `name.ts` にある数え方を共有の `src/lib/text.ts`（`countCharacters`）に移して両方で使う

#### 画面の部品（U-2）

| 部品          | 表示するもの                                                                                                          | 受け取るもの                   | 対象の AC        |
| ------------- | --------------------------------------------------------------------------------------------------------------------- | ------------------------------ | ---------------- |
| `DiaryEditor` | 日付・「今日はどんな一日だった？きかせて！」・入力欄・文字数（`0 / 2000`）・エラー・「日記をのこす」                  | 日記の日付・保存するときの関数 | AC-5, AC-7, AC-8 |
| `TodayEntry`  | 日付・「今日も書いてくれてありがとう！また明日ね」・本文（改行もそのまま）・「次の日記は、明日の朝 4 時から書けるよ」 | 日記                           | AC-14            |

- 部品は表示と入力の受け取りだけを受け持つ。「今日の日記があるか」で `DiaryEditor` と `TodayEntry` を切り替えるのは U-3（Bolt-3）
- 入力欄には読み上げ機能向けの見出し「今日の日記」を付ける（画面には見せない）
- 文字数の表示は入力のたびに更新する。2000 文字を超えたら数字を注意の色にする
- エラーの文言はモックのとおり（「なにか書いてくれるとうれしいな」「2000 文字までにしてね（いま N 文字）」）

#### ファイルの置き場所

```
src/lib/
├─ diary-date.ts / diary-date.test.ts   # getDiaryDate・formatDiaryDate
└─ text.ts / text.test.ts               # countCharacters（name.ts から移す）
src/features/diary/
├─ diary.ts / diary.test.ts             # DiaryEntry 型・validateBody・本文の上限
├─ DiaryEditor.tsx / DiaryEditor.test.tsx
└─ TodayEntry.tsx / TodayEntry.test.tsx
```

#### ⑥ で書くテスト（例）

- `getDiaryDate`：28 日 23:00 → `2026-10-28`／29 日 3:59 → `2026-10-28`／29 日 4:00 → `2026-10-29`／月や年をまたぐ日（11 月 1 日 2:00 → `2026-10-31`、1 月 1 日 3:00 → 前の年の `12-31`）
- `formatDiaryDate`：`2026-10-28` → `2026年10月28日（水）`
- `validateBody`：「晴れた」→ 成功／前後の空白・改行を除く・途中の改行は残す／空・空白や改行だけ → `empty`／2000 文字 → 成功／2001 文字 → `tooLong` と文字数
- `countCharacters`：絵文字や合成文字を 1 と数える（名前のテストもそのまま通ること）
- 部品：日付と入力欄の表示、文字数の表示、エラーの文言、保存の関数に整えた本文が渡ること、今日の日記の本文と改行の表示

#### ADR

この Bolt でも、技術の選定を伴う判断はないため ADR は作らない。ブラウザ内への保存は Bolt-3 で ADR-0002 として残す。

## PR の単位

Bolt は 4 つで、どれも数時間〜1 日の大きさ。ルールどおり、この機能は 1 ブランチ・1 PR（`feat/diary-exp`）で進める。

## 判断メモ

- Units へのゲートでの判断：指摘なしで承認（1 ブランチ・1 PR のまま。④ UI モックは作る）

- Bolt-1 ⑤ 設計へのゲートでの判断：「けいけんち」を漢字の「経験値」に修正（mockup.md・mockup.html も合わせて修正）。修正後の内容で承認
- Bolt-2 ⑤ 設計の作成前に確認した点：本文は前後の空白・改行だけを取り除く／日付は年も入れて「2026年10月28日（水）」と表示する（モックも修正）
- Bolt-2 ⑤ 設計へのゲートでの判断：指摘なしで承認
