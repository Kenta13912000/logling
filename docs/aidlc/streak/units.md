# Units：連続記録とボーナス（streak）

## U-1：連続記録とボーナス（`src/features/streak/`）

- 含む Story：S-1, S-2, S-3, S-4, S-5, S-6
- 依存：
  - `src/features/home/`（保存データ・ホームの画面。ホームに連続日数を出し、日記を保存するときにボーナスを足す）
  - `src/features/diary/`（日記のデータの形。日記にボーナスの記録を加える）
  - `src/features/character/`（経験値とレベルの計算。ボーナスもいつもの経験値と同じく足す）
  - `src/features/history/`（日記を消すときの減る経験値。ボーナスを含めるようにする）

連続日数の計算・次の区切り・ボーナスの量のきまりは、どれも「連続記録」の話なので、1 つの Unit にまとめる。ホームや振り返りの画面には、この Unit の計算を呼び出す形で組み込む。

### Bolt 計画

- Bolt-1：データの形と計算。連続日数・次の区切り・ボーナスの量・日記ごとの経験値（ボーナスを含む）を求める（AC-4, AC-5, AC-8, AC-11〜AC-14, AC-21）
- Bolt-2：ホームに連続日数と次の区切りを表示する（AC-1〜AC-3, AC-6, AC-7）
- Bolt-3：今日の日記を書いたときにボーナスを入れ、お知らせを出す。ボーナスの付いた日記を消す・書き直すときの扱い（AC-9, AC-10, AC-15〜AC-20）
- Bolt-4：スマホ幅での表示と、連続記録の一連の操作の E2E テスト（AC-22）

### 設計（⑤で追記）

#### Bolt-1：データの形と計算

**ファイル**

```
src/features/streak/streak.ts / .test.ts   # 連続日数・次の区切り・ボーナスの量の計算（画面に依存しない）
src/features/diary/diary.ts                # 日記にボーナスの記録（bonus）を加える
src/features/home/save-data.ts / .test.ts  # 読み込むときに bonus の形を確かめる
src/features/history/history.ts / .test.ts # 日記ごとの経験値（expForEntry）にボーナスを含める
```

**保存データの形の変更**（`version` は 1 のまま。記録がなくても読めるため）

```ts
type DiaryEntry = {
  date: string;
  body: string;
  createdAt: string;
  writtenLater?: true;
  /** その日に書いて連続が区切りに届いたときのボーナス経験値。ほかの日記にはない */
  bonus?: number;
};
```

- `bonus` は、ないか、1 以上の整数。それ以外は壊れたデータとして扱う（`writtenLater` と同じ確かめ方）
- `bonus` がない日記は、ボーナス 0 として扱う（AC-21）。この機能より前の日記にも、さかのぼって付けない（AC-14）

**計算（`streak.ts`）**

| 関数                                 | 中身                                                                                                                                           |
| ------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `bonusForStreak(days)`               | 区切りの日数ならボーナスの量、そうでなければ 0。3 日：10、7 日：20、14 日：30、30 日：50、そのあと 15 日ごと（45・60・75…）：50（AC-8, AC-11） |
| `nextMilestone(days)`                | `days` より大きい、いちばん近い区切りの日数と、そのボーナスの量（AC-7, AC-8）                                                                  |
| `countStreak(entries, endDate)`      | `endDate` から 1 日ずつさかのぼり、日記が途切れずにある日数。`endDate` に日記がなければ 0。後から書いた日記も数える（AC-5）                    |
| `getStreakStatus(entries, today)`    | ホームに出す内容をまとめて返す（下の表）                                                                                                       |
| `bonusForTodayEntry(entries, today)` | 今日の日記を書いたときに入るボーナス。「昨日までの連続 + 1」が区切りならその量、そうでなければ 0（AC-9, AC-11, AC-13, AC-17）                  |

`getStreakStatus` が返すもの：

| 項目           | 中身                                                                                                     |
| -------------- | -------------------------------------------------------------------------------------------------------- |
| `writtenToday` | 今日の日記があるか                                                                                       |
| `days`         | 今日の日記があれば今日までの連続日数、なければ昨日までの連続日数（昨日もなければ 0）（AC-1〜AC-3）       |
| `next`         | 次の区切りの日数・ボーナスの量・あと何日か。あと何日かは今日を含めて数える（`next.days - days`）（AC-7） |

- 例（今日まだ書いていない、昨日まで 4 日）：`days = 4`、次は 7 日でボーナス 20、あと 3 日。今日書くと何日になるかは `days + 1` で画面が出す
- 「今日」は、ホームと同じく朝 4 時で区切った日付を渡す（AC-4）。この Unit の計算は、日付の文字列だけを扱い、時刻を読まない
- 後から書いた日記にはボーナスを付けない（`writeLaterEntry` は今のまま。AC-12）。ボーナスを計算するのは、ホームで今日の日記を書くときだけ（Bolt-3 で組み込む）

**経験値（`history.ts`）**

- `expForEntry(entry)` を「日記の経験値（その日なら 10、後からなら 5）+ `bonus`」にする。消すときに減る量（`previewDelete`・`deleteEntry`）は、これをそのまま使うので、ボーナスも一緒に減る（AC-16）
- 書き直し（`editEntry`）は本文だけを変えるので、`bonus` はそのまま残る（AC-18）

**⑥ で書くテスト（例）**

- `bonusForStreak`：3・7・14・30・45・60 日はボーナスがあり、1・2・4・29・31・44 日は 0（AC-8, AC-11）
- `nextMilestone`：0 → 3 日、3 → 7 日、29 → 30 日、30 → 45 日、45 → 60 日（AC-7, AC-8）
- `countStreak`：途切れたところで止まる／後から書いた日記も数える（AC-5）／月や年をまたいでも数えられる
- `getStreakStatus`：今日あり・今日なしで昨日まで連続・昨日も今日もなし（AC-1〜AC-3）／朝 4 時前は前の日を今日として数える（AC-4）
- `bonusForTodayEntry`：区切りに届くとき・届かないとき／途切れたあとまた届くとき（AC-13）／今日の日記を消したあとにもう一度書くとき（AC-17）
- `save-data`：`bonus` がある日記・ない日記を読める／形のおかしい `bonus` は壊れたデータになる（AC-19, AC-21）
- `history`：ボーナスの付いた日記の `expForEntry` は合計／消すとボーナスも減る／書き直してもボーナスは残る（AC-16, AC-18）

**ADR**

新しい技術の選定はないため、ADR は作らない。保存データの形の変更（`bonus` の追加）は、この units.md に記録する。

#### Bolt-2：ホームに連続日数と次の区切りを表示する

**ファイル**

```
src/features/streak/StreakBand.tsx / .test.tsx    # 🔥 の帯。getStreakStatus の結果を受け取って 2 行を出す（画面の部品だけ）
src/features/character/CharacterStatus.tsx       # 経験値のバーの下に、帯を入れる場所（children）を加える
src/features/home/Home.tsx / .test.tsx           # 保存データの日記と「今日」から getStreakStatus を求め、帯を渡す
```

- 帯は、モックどおりステータス（白い区画）の中、経験値のバーのすぐ下に置く。`CharacterStatus` は帯の中身を知らず、受け取ったものを並べるだけにする（キャラクターの部品が連続記録の部品に依存しないようにするため）
- 帯を出すのは、キャラクターがいて、日記を書く・書いた画面のときだけ（名前を付ける前や、データが壊れているときは、ステータスそのものが出ない）

**帯の文言**（`StreakBand`）

| 状態                                       | 1 行目                               | 2 行目                                 |
| ------------------------------------------ | ------------------------------------ | -------------------------------------- |
| 今日書いた（`writtenToday`）               | 「🔥 5 日連続」                      | 「あと 2 日で 7 日連続。ボーナス +20」 |
| 今日まだ・昨日まで続いている（`days` ≥ 1） | 「🔥 4 日連続中。今日書くと 5 日！」 | 「あと 3 日で 7 日連続。ボーナス +20」 |
| 今日まだ・続いていない（`days` = 0）       | 「🔥 今日書くと 1 日目！」           | 「あと 3 日で 3 日連続。ボーナス +10」 |

- 数字は `getStreakStatus` の結果から作る（「今日書くと」の日数は `days + 1`）
- 🔥 は飾りなので、読み上げでは読ませない（`aria-hidden`）。帯全体に「連続記録」という名前を付け、読み上げ機能でもまとまりがわかるようにする
- 色はモックどおり、経験値のバーの下地と同じ薄いはちみつ色（`honey-track`）

**「今日」と更新のタイミング**

- 「今日」は、ホームがすでに使っている `useToday` の値（朝 4 時で区切った日付）を渡す（AC-4）
- 日記を保存すると保存データが変わり、ホームが描き直されるので、帯も「今日書くと 5 日！」から「5 日連続」に変わる。開き直したときも、保存されている日記から同じ値を計算する（AC-6）

**⑥ で書くテスト（例）**

- `StreakBand`：3 つの状態の 1 行目と 2 行目（AC-1〜AC-3, AC-7）／帯に「連続記録」の名前がある
- `Home`：日記のあるデータで帯が出る（AC-1）／今日まだのときは「今日書くと」が出て、日記を書くと「N 日連続」に変わる（AC-2）／開き直しても同じ表示（AC-6）／名前を付ける前は帯がない

**ADR**

この Bolt でも ADR は作らない。

#### Bolt-3：今日の日記でボーナスを入れる・消すときの扱い

**ファイル**

```
src/features/diary/diary.ts                           # 日記に、ボーナスをもらったときの連続日数（bonusDays）を加える
src/features/home/save-data.ts / .test.ts             # bonus と bonusDays がそろっているかを確かめる
src/features/home/Home.tsx / .test.tsx                # 今日の日記を保存するときに、ボーナスを計算して足す
src/features/character/ExpGainToast.tsx / .test.tsx   # お知らせに、ボーナスの行を出せるようにする
src/features/history/history.ts / .test.ts            # 消す前の見込み（previewDelete）に、ボーナスの量を加える
src/features/history/DeleteDialog.tsx / .test.tsx     # ボーナスが付いているときだけ、内訳を出す
src/features/history/HistoryPage.tsx / .test.tsx      # 見込みのボーナスを確認の窓に渡す
```

**今日の日記を保存するとき（ホーム）**

1. 保存する日付は、これまでどおりその場で計算し直す（朝 4 時の区切り。AC-4）
2. `bonusForTodayEntry(日記, 日付)` でボーナスを求める。届いた連続日数は「昨日までの連続日数 + 1」
3. 経験値は「10 + ボーナス」を一度に足す（`gainExp`）。レベルが上がったら、これまでどおりレベルアップのお知らせを出す（AC-10）
4. 日記には、ボーナスがあるときだけ `bonus`（量）と `bonusDays`（届いた連続日数）を付けて保存する（AC-19）。ボーナスがないときは今までと同じ形
5. 保存に失敗したら、日記も経験値もボーナスも変わらず、お知らせも出さない（AC-20。今の作りのまま）
6. 今日の日記を消してから書き直したときも、同じ計算をするので、区切りならボーナスがまた入る（AC-17）

**お知らせ（`ExpGainToast`）**

- これまでの「✨ +10 経験値！」に、ボーナスがあるときだけ 2 行目「🔥 7 日連続！ボーナス +20」を加える（AC-9）
- 渡すものを「増えた経験値」から「増えた経験値と、ボーナス（連続日数と量。ないときは渡さない）」に広げる。1 行目はこれまでどおり日記の分（10）
- 1 つのお知らせに 2 行（モックの判断どおり）。出ている時間は今と同じ 2.5 秒

**消すとき（振り返り）**

- `previewDelete` が返すものに、その日記のボーナス（`bonus` と `bonusDays`。ないときは渡さない）を加える
- 確認の窓は、ボーナスが付いているときだけ、モックどおり内訳を小さく出す：「（日記の 10 と、7 日連続のボーナス 20）」（AC-15）
- 減る量と、消したときの処理は、Bolt-1 で `expForEntry` にボーナスを含めたので、そのまま正しく動く（AC-16）

**保存データの形の追加**（`version` は 1 のまま）

```ts
type DiaryEntry = {
  // …Bolt-1 までと同じ…
  bonus?: number;
  /** ボーナスをもらったときの連続日数（例：7）。bonus と必ずセットで記録する */
  bonusDays?: number;
};
```

- 内訳に「7 日連続」と出すために足す。量（`bonus`）から日数を逆算すると、30 日以降は同じ 50 が何度も出てきて決められないため、日数も記録する
- 読み込むときは、`bonus` と `bonusDays` が両方ないか、両方とも 1 以上の整数かを確かめる。片方だけ、またはおかしな値なら壊れたデータとして扱う
- Bolt-1 の「ボーナスの記録がある日記を読める」テスト（`bonus` だけを持つ日記）は、`bonusDays` も持つ形に直す。そのほかの Bolt-1 のテストは変えない

**⑥ で書くテスト（例）**

- `ExpGainToast`：ボーナスがあれば 2 行目が出る／なければ 1 行だけ（AC-9）
- `DeleteDialog`：ボーナスがあれば「（日記の 10 と、7 日連続のボーナス 20）」の内訳が出る／なければ出ない（AC-15）
- `history`：`previewDelete` がボーナスの量と日数を返す（AC-15）
- `save-data`：`bonus` と `bonusDays` がそろった日記を読める／片方だけ・おかしな値は壊れたデータになる（AC-19）
- `Home`：書いて 7 日に届くと、お知らせに 2 行が出て、保存データの日記に `bonus: 20`・`bonusDays: 7`、経験値が 30 増える（AC-9, AC-19）／ボーナスでレベルが上がるとレベルアップのお知らせが出る（AC-10）／区切りでない日は 1 行だけで `bonus` もない（AC-11）／保存に失敗するとボーナスも入らない（AC-20）
- `HistoryPage` から `Home`：ボーナスの付いた今日の日記を消すと 30 減り、そのあとホームで書き直すと、また 30 入る（AC-16, AC-17）
- `HistoryPage`：確認の窓に「消すと経験値が 30 減るよ。」と「（日記の 10 と、7 日連続のボーナス 20）」が出る（AC-15）

**ADR**

この Bolt でも ADR は作らない。

#### Bolt-4：スマホ幅での表示と E2E テスト

**ファイル**

```
e2e/streak.spec.ts    # 連続記録の一連の操作を、幅 375px の本物のブラウザ（Chromium）で確かめる
```

- 画面の作りは Bolt-2・Bolt-3 でできている。この Bolt では E2E テストで確かめ、崩れが見つかったときだけ直す（`diary-history` の Bolt-5 と同じ進め方）

**日付と保存データ**

- `diary-history` の E2E テストと同じく、`page.clock.setFixedTime` でブラウザの中の時刻を「2026 年 11 月 8 日 21 時」に固定する
- 保存データは、11 月 2 日〜7 日の 6 日分の日記（その日に書いたもの）を入れておく。今日（11 月 8 日）書くと 7 日連続になる
- 経験値は 40（レベル 2 の 10 / 40）にしておく。7 日目を書くと 30 入って 70 になり、レベル 3 に上がる

**確かめること**

| テスト                                                                                                                              | 対象の AC         |
| ----------------------------------------------------------------------------------------------------------------------------------- | ----------------- |
| 書く前は「🔥 6 日連続中。今日書くと 7 日！」「あと 1 日で 7 日連続。ボーナス +20」が出る                                            | AC-2, AC-7        |
| 書くと、お知らせに「✨ +10 経験値！」「🔥 7 日連続！ボーナス +20」が出て、レベルアップのお知らせも出る。帯は「🔥 7 日連続」に変わる | AC-1, AC-9, AC-10 |
| 再読み込みしても、帯と経験値（レベル 3 の 0 / 50）が残っている                                                                      | AC-6, AC-19       |
| 振り返りで今日の日記を消すと、確認に「消すと経験値が 30 減るよ。」と内訳が出て、消したあとホームの帯は「今日書くと 7 日！」に戻る   | AC-15, AC-16      |
| ホーム（帯・お知らせ）と、振り返りの確認の窓（内訳あり）のどれでも、横スクロールが出ない                                            | AC-22             |
| 一連の操作の間、同じオリジン以外へ通信せず、本文も送らない                                                                          | AC-19             |

- 公開中のサイトに対しても、`BASE_URL` を指定すれば同じテストを実行できる。マージしてデプロイしたあとに実行する

**ADR**

## 実装の順番

| 順番 | Bolt   | 内容                             | 理由                                                                             |
| ---- | ------ | -------------------------------- | -------------------------------------------------------------------------------- |
| 1    | Bolt-1 | データの形と計算                 | 連続日数とボーナスのきまりを最初に固める。画面に依存せず、テストしやすい         |

## PR の単位

Bolt は 4 つで、`diary-history`（Bolt 5 つ・1 PR）より小さい。ルールどおり、1 ブランチ・1 PR（`feat/streak`）で進める。

## ④ UI モックについて

ホームのステータスの近くに連続日数と次の区切りを出し、日記を保存したときのお知らせにボーナスを加える。画面が変わるので、`diary-history` と同じく HTML のモックを作ることを提案する。

## 判断メモ

- Units へのゲートでの判断：指摘なしで承認（1 ブランチ・1 PR のまま。④ UI モックは HTML で作る）
- Bolt-1 ⑤ 設計へのゲートでの判断：指摘なしで承認（ボーナスはその日の日記に記録する。計算は日付の文字列だけを扱う）
- Bolt-1 ⑥ テスト作成へのゲートでの判断：指摘なしで承認（今の作りで通る AC-12・AC-18・AC-21 のテストも、壊さないための見張りとして残す）
- Bolt-1 ⑦ 実装へのゲートでの判断：指摘なしで承認（区切りのきまりは `streak.ts` の先頭にまとめた）
- Bolt-2 ⑤ 設計へのゲートでの判断：指摘なしで承認（帯はステータスの中に置き、中身はホームから渡す）
- Bolt-2 ⑥ テスト作成へのゲートでの判断：指摘なしで承認（名前を付ける前は帯を出さないテストも、見張りとして残す）
- Bolt-2 ⑦ 実装へのゲートでの判断：指摘なしで承認
- Bolt-3 ⑤ 設計へのゲートでの判断：修正を依頼（消す前の確認の内訳に、モックどおり「7 日連続」の日数も出す。そのため日記に bonusDays を足す）。修正後の設計は、中断をはさんで再開時に指摘なしで承認
- Bolt-3 ⑥ テスト作成へのゲートでの判断：指摘なしで承認（今の作りで通る AC-11・AC-20・内訳なしのテストも、見張りとして残す）
