# Units：キャラの名前を変える・暗い色の画面（settings）

## U-1：キャラの名前を変える（`src/features/rename/`）

- 含む Story：S-1, S-2, S-3
- 依存：
  - `src/features/character/`（名前の決まり `validateName`。名前を付ける画面の確認の文を直す）
  - `src/features/cloud/`（ログイン中に、保管場所の名前を書きかえる処理を足す。`useDiaryData` の保存の種類に「名前を変える」を足す）
  - `src/features/navigation/`（「設定」の画面のいちばん上に「キャラクター」のまとまりを置く）

名前を変える入口と流れ、保存（ブラウザの中・保管場所）。経験値や日記には触れない。

### Bolt 計画

- Bolt-1：「設定」の「キャラクター」、名前を変える流れ（入力・確認・保存）、ブラウザの中と保管場所への保存、失敗とほかの端末で変わっていたとき、名前を付ける画面の文（AC-1〜AC-10、AC-15 の名前の部分）

## U-2：暗い色の画面（`src/features/theme/`）

- 含む Story：S-4, S-5
- 依存：
  - `src/app/`（色の決まり `globals.css`、ブラウザの上の帯の色 `layout.tsx`）
  - 色を直接書いている部品（白い背景、薄いオレンジ、タブ、お知らせ、確認の窓、ログインのボタンなど）

色の決まりを、明るい色と暗い色の 2 組にし、端末の設定で切り替える。画面の動きには触れない。

### Bolt 計画

- Bolt-2：色の決まりを 2 組にし、直接書いている色を決まりの名前に置きかえる。キャラクターの絵・タブ・お知らせ・確認の窓の見え方。ブラウザの上の帯の色。読みやすさ（明るさの差）と幅 375px の E2E（AC-11〜AC-15）

## 取り込みの依頼（PR）の分け方

- 1 つの PR（ブランチ `feat/settings`）にまとめる。2 回分の小さな機能のため
- DB の表は変えないので、取り込む前の本番の準備は要らない。取り込んだあとに、公開中のサイトで E2E テストを動かし、開発者の iPhone で、名前の変更と暗い色を確かめる

### 設計（⑤で追記）

#### Bolt-1：「設定」の「キャラクター」と、名前を変える流れ

DB の表は変えない（`characters.name` を書きかえるだけ）。新しい部品や技術も入れないため、ADR は作らない。

**データの流れ**

- 「キャラクター」のまとまりは、ホームや振り返りと同じ `useDiaryData` で読み書きする。ログインしていないときはブラウザの中、ログイン中はインターネット上の保管場所
- `useDiaryData` の保存の種類（`Change`）に `{ type: "renameCharacter"; name }` を足す。ブラウザの中には、名前だけを変えた `SaveData` をそのまま書く（経験値・始めた日・日記はそのまま：AC-6）
- ほかの画面への反映（AC-7）
  - ブラウザの中：今と同じく、書きかえると開いているすべての画面に知らせが行く（`useSaveData`）
  - 保管場所：ホームや振り返りは、画面を開き直すたびに保管場所から読み直す（今の振り返りで日記を消したときと同じ）
  - 書き忘れのお知らせの文は、送るときに保管場所の名前を読むので、何も変えなくても新しい名前になる

**名前の決め方**（`src/features/rename/rename.ts`。画面に依存しない関数）

`planRename(今の名前, 入れた文字)` で、次のどれかを返す。

| 結果                 | 条件                                         | 画面                                   |
| -------------------- | -------------------------------------------- | -------------------------------------- |
| 正しくない           | 空・11 文字以上（`validateName` と同じ）     | 「⚠ 名前を入れてね」などを出す（AC-3） |
| 同じ                 | 前後の空白を除くと、今の名前と同じ           | 保存せずに閉じる（AC-3）               |
| 確認へ（新しい名前） | それ以外。前後の空白を除いた名前を確認に出す | 「『<新しい名前>』に変える？」（AC-2） |

**画面の状態**（`src/features/rename/CharacterSettings.tsx`）

```
ふだん ──「名前を変える」──▶ 入力 ──「この名前にする」──▶ 確認 ──「変える」──▶ 保存中 ──▶ ふだん
  ▲                          │「やめる」                │「やめる」                  （失敗・なくなっていた：
  └──────────────────────────┘                          └──▶ 入力                      お知らせを出して ふだん）
```

- 入力に入ると入力欄に、確認に入ると確認の文に、ふだんに戻ると「名前を変える」ボタンに、キーボードの位置（フォーカス）を移す（画面の読み上げで、変わったことがわかるように）
- 保存中は「変える」が「保存しているよ…」になり、「変える」「やめる」とも押せない（AC-9）
- 保存の結果
  - 成功：ふだんに戻り、新しい名前が出る
  - 失敗：ふだんに戻り、前の名前のまま、カードの中に「⚠ 保存できなかった…通信できるところで、もう一度ためしてね」（AC-9）
  - ほかの端末でキャラクターがなくなっていた：保管場所の最新の内容に切りかえ（名前を付ける前の表示になる）、「⚠ ほかの端末で、キャラクターがなくなっていたよ。最新の内容を表示したよ」（AC-10）
  - お知らせは、もう一度「名前を変える」を押すと消える
- 名前を付ける前は「まだ名前がないよ。ホームで名前を付けてね ›」（ホームへのリンク：AC-4）
- データを読めないとき（AC にない場面。ホームと同じ扱いにする）
  - 読み込み中：「読み込んでいるよ…」
  - 保管場所を読めなかった：「データを読み込めなかった…」と「もう一度読み込む」
  - ブラウザの中のデータがこわれている：「データを読めなかったよ。ホームで直してね ›」（直す操作はホームにだけ置く）

**サーバーの処理**（`src/features/cloud/actions.ts` に足す。`"use server"`）

| 処理                         | 中身                                                                                                                 | 結果                                                                   |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| `renameCloudCharacter(name)` | 名前を `validateName` で確かめ、ログインしている人のキャラクターの名前だけを書きかえる。持ち主はログイン情報で決める | 成功（最新の内容）／キャラクターがない（最新の内容）／正しくない／失敗 |

- `repository.ts` に `renameCharacter(db, userId, name)` を足す。行がなければ「キャラクターがない」（`noCharacter`）を返し、`latest` で最新の内容を付けて返す（今の衝突の扱いと同じ）
- `validate.ts` に `parseName(value)` を足す（文字でないとき・決まりに合わないときは null）
- 失敗したときに、名前を記録（ログ）に出さない（今の `withUser` のまま）

**名前を付ける画面**（AC-5）

- `NameForm.tsx` の確認の文を「名前はあとから『設定』で変えられるよ」にする。ほかは変えない

## 判断メモ

- Units へのゲートでの判断：指摘なしで承認（2 つのかたまり、2 回、PR は 1 つ。暗い色の色合いと名前を変える流れは ④ の画面の見本で確かめる）
- Bolt-1 の設計へのゲートでの判断：指摘なしで承認（データを読めないときはホームと同じ扱い、お知らせは次に「名前を変える」を押すまで残す、ADR は作らない）
- Bolt-1 ⑥ へのゲートでの判断：指摘なしで承認（これまでのテストで直したのは、名前を付ける画面の確認の文 AC-5 の 1 か所だけ。振り返りの名前は、日記を消す確認の「レベルが下がるよ」の文で確かめる）
- Bolt-1 ⑦ へのゲートでの判断：指摘なしで承認（名前の誤りの文を `name.ts` にまとめて、名前を付ける画面と共有した。iPhone で画面が拡大されないよう、入力欄の文字は 16px にした）
