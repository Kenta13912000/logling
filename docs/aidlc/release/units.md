# Units：公開（release）

## 全体像

この機能はアプリの画面を作らないため、Unit は `src/features/` のフォルダではなく、作業のまとまりで分ける。

```
U-1 配信の設定（リポジトリの中の設定とテスト）
 └─ U-2 Vercel との連携（Vercel の画面での操作と ADR）
     └─ U-3 公開の仕上げ（README・リポジトリの公開）
```

## U-1：配信の設定（`next.config.ts`・`playwright.config.ts`・`e2e/`）

- 含む Story：S-4（S-1 の確かめ方も用意する）
- 依存：なし
- 受け持つこと：基本的なセキュリティの設定（レスポンスヘッダー）、外部への通信がないことを確かめる E2E テスト、E2E テストを公開版の URL に向けても実行できるようにする設定

### Bolt 計画

- Bolt-1：セキュリティの設定と、外部への通信・計測のスクリプトがないことを確かめる E2E テスト。手元でも公開版でも同じテストを実行できるようにする（AC-8, AC-9, AC-10）

### 設計（⑤で追記）

#### セキュリティの設定（`next.config.ts` の `headers()`。すべてのページに付ける）

| ヘッダー                  | 値                                | 目的（AC-10）                                                                         |
| ------------------------- | --------------------------------- | ------------------------------------------------------------------------------------- |
| `Content-Security-Policy` | `frame-ancestors 'none'`          | ほかのサイトの中に埋め込まれない（偽の画面に重ねて操作させる攻撃を防ぐ）              |
| `X-Frame-Options`         | `DENY`                            | 上と同じ。`frame-ancestors` に対応していない古いブラウザ向け                          |
| `X-Content-Type-Options`  | `nosniff`                         | ファイルの種類をブラウザに推測させない（種類を偽ったファイルの実行を防ぐ）            |
| `Referrer-Policy`         | `strict-origin-when-cross-origin` | 別のサイトへ移動するとき、ページの URL は伝えず、サイトの名前（オリジン）だけを伝える |

- Next.js 16 の公式ドキュメントで、埋め込みの防止は `X-Frame-Options` より CSP の `frame-ancestors` が推奨されていることを確かめた。古いブラウザのために両方を付ける
- CSP は `frame-ancestors` だけにする。スクリプトの読み込み元まで制限する本格的な CSP は、Next.js のインラインのスクリプトとの調整が必要になるため、この機能では扱わない
- HTTPS への切り替え（AC-3）と `Strict-Transport-Security` は Vercel が付けるかを Bolt-2 で確かめる。手元の開発サーバーは HTTP なので、ここでは付けない

#### E2E テストを公開版にも向けられるようにする（`playwright.config.ts`）

- 環境変数 `BASE_URL` があれば、その URL に向けてテストする。なければ、これまでどおり手元で開発サーバーを起動してテストする
- 例：`$env:BASE_URL = "https://logling-xxxx.vercel.app"; npm run test:e2e`
- PR ごとの確認用の URL は本人しか見られない設定（AC-7）のため、テストは公開版（`main` の URL）に向けて実行する

#### 追加する E2E テスト（`e2e/release.spec.ts`）

| テスト                         | 確かめること                                                                                                     | 対象の AC |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------- | --------- |
| 外部への通信がない             | 名前を付けて日記を保存するまでに起きた通信が、すべてページと同じオリジン宛てで、送信の中に日記の本文が含まれない | AC-8      |
| 計測のスクリプトを読み込まない | ページの中のスクリプト（`<script src>`）が、すべてページと同じオリジンから読み込まれている                       | AC-9      |
| セキュリティの設定             | トップページの応答に、上の 4 つのヘッダーが付いている                                                            | AC-10     |

- `diary-exp` の E2E テスト（`e2e/diary-exp.spec.ts`）も、`BASE_URL` を付ければ公開版で動く（AC-1, AC-2 の確認に使う）

#### ADR

この Bolt では ADR は作らない（公開先の ADR-0003 は Bolt-2 で作る）。

## U-2：Vercel との連携（Vercel の画面・`docs/adr/0003-*.md`）

- 含む Story：S-1, S-2, S-3, S-6
- 依存：U-1（公開する前に、セキュリティの設定とテストをそろえておく）
- 受け持つこと：公開先の比較と ADR-0003、Vercel のアカウントの作成とプロジェクトの作成（開発者が画面で操作する）、最初の公開、公開版での確認

### Bolt 計画

- Bolt-2：ADR-0003 を書き、Vercel と GitHub を連携して公開する。公開版で E2E テストと手動の確認を行う（AC-1, AC-2, AC-3, AC-4, AC-5, AC-6, AC-7, AC-13。AC-8〜AC-10 は公開版でも確かめる）

### 設計（⑤で追記）

#### 公開先

Vercel の無料プラン（Hobby）を使う。選んだ理由と、公式の情報で確かめた条件は [ADR-0003](../../adr/0003-hosting-vercel.md) に残す。

#### リポジトリの中で変えること

| ファイル       | 変更                                                   | 理由                                                                                                       |
| -------------- | ------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------- |
| `package.json` | `engines.node` を `>=24.22.1` から `^24.22.1` に変える | Vercel は「以上」の指定だと最新の Node 26 を使う（公式ドキュメント）。手元・CI と同じ Node 24 で動かすため |
| `docs/adr/`    | ADR-0003 を追加                                        | AC-13                                                                                                      |

- Vercel の設定ファイル（`vercel.json`）は作らない。Next.js は Vercel が自動で認識し、ビルドの命令（`npm run build`）も標準のままでよいため
- 環境変数（秘密の値）は使わない。アプリはサーバーの秘密情報を持たない

#### Vercel の画面で行う操作（開発者が行う。手順とセキュリティ上の意味はそのつど説明する）

| 順番 | 操作                                                                                                            | セキュリティの観点                                                        |
| ---- | --------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| 1    | Vercel に GitHub のアカウントで登録する（無料プラン）                                                           | パスワードを新しく作らずに済む                                            |
| 2    | Vercel の GitHub アプリに、**logling のリポジトリだけ**へのアクセスを許可する（「すべてのリポジトリ」にしない） | 必要な最小限の権限にする                                                  |
| 3    | logling を取り込み（Import）、設定は標準のまま公開する（Deploy）                                                | 環境変数は入れない                                                        |
| 4    | 「Deployment Protection」が標準の **Standard Protection（Vercel Authentication）** になっていることを確かめる   | 本番の URL だけを公開し、PR ごとの確認用の URL は本人だけに見せる（AC-7） |
| 5    | Web Analytics・Speed Insights は有効にしない                                                                    | 利用者の情報を集めない（AC-9）                                            |

## 判断メモ

- Units へのゲートでの判断：指摘なしで承認。新しい画面がないため ④ UI モックは作らない
- Bolt-1 ⑤ 設計へのゲートでの判断：指摘なしで承認（CSP は frame-ancestors だけにする）
- Bolt-1 ⑦ 実装へのゲートでの判断：指摘なしで承認
- Bolt-2 ⑤ 設計の作成前に確認した点：比べる相手（Netlify・Cloudflare）も公式の情報を調べる。調べた結果、Vercel が `>=` の指定では Node 26 を使うことがわかり、`engines.node` を `^24.22.1` に変える
- Bolt-2 ⑤ 設計へのゲートでの判断：指摘なしで承認（ADR-0003 も承認。Node は 24 のまま）
- Bolt-2 ⑦ で見つかったこと：`npm audit` で開発用ツール（ESLint が使う `minimatch`）に中程度の脆弱性 17 件（GHSA-g3hv-75wg-m249）。本番用のパッケージは 0 件で、悪用の経路もないため、記録して ESLint 側の対応を待つ。リポジトリの公開後に Dependabot を有効にする（⑧ の差分レポートに残す）
- Bolt-2 ⑦ の途中で中断：リポジトリの中の変更（`engines.node`）はコミット・push 済み。Vercel の画面での操作（登録 → logling だけを許可 → 取り込んで公開）から再開する
- Bolt-2 ⑦ で再開：Vercel で公開し、本番の URL は https://logling.vercel.app になった。チーム名は実名を出さないよう GitHub のユーザー名にした
- Bolt-2 ⑦ 実装へのゲートでの判断：指摘なしで承認（AC-4・AC-6・AC-7・AC-10 は PR を作ってから確かめる）
