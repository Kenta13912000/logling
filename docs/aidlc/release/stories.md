# Stories：公開（release）

## S-1：URL を開くだけで試せる（対象：SC-1）

採用担当者として、URL を開くだけで logling を試したい。なぜなら、インストールや準備が必要だと、短い時間で実際の動きを確かめられないから。

- AC-1：公開の URL（`〜.vercel.app`）を開くと、見出し「logling」が表示され、タブのタイトルが「logling」になっている
- AC-2：公開版で、名前を付ける → 確認 → 日記を保存 → 経験値が入る、までの操作が、幅 375px のスマホと PC の画面の両方でできる
- AC-3：公開版は HTTPS で配信され、`http://` で開いても HTTPS に切り替わる

## S-2：マージすると公開版が更新される（対象：SC-2）

開発者として、`main` にマージしたら公開版も自動で新しくしたい。なぜなら、手作業で公開すると忘れたり間違えたりするから。

- AC-4：`main` にマージすると、Vercel が自動でビルドし、公開版が新しい内容になる（手作業の操作はいらない）
- AC-5：ビルドに失敗したときは、公開版は前の内容のまま残る

## S-3：PR ごとに確認用の URL ができる（対象：SC-3）

開発者として、PR を取り込む前に、変更後の画面を実物で確かめたい。なぜなら、スマホでの見た目などはテストだけではわからないから。

- AC-6：PR を作ると、その PR の変更を反映した確認用の URL が、PR のページに表示される
- AC-7：確認用の URL は、Vercel にログインした開発者本人しか見られない（作りかけの画面を一般に公開しない）

## S-4：公開しても日記は外に出ない（対象：SC-4）

日記を書く人として、公開されたアプリを使っても、日記の内容が外に送られないでほしい。なぜなら、日記は人に見せたくない個人的な内容だから。

- AC-8：公開版で名前を付けて日記を保存するまでの間、ページと同じ場所（公開の URL）以外への通信が起きず、日記の内容を含む送信もない
- AC-9：アクセス解析や速度計測などの、利用者の情報を集めるスクリプトを読み込んでいない
- AC-10：公開版は、基本的なセキュリティの設定をしたうえで配信される（ほかのサイトの中に埋め込まれない、ファイルの種類を偽れない、移動先のサイトに元のページの URL を詳しく伝えない）

## S-5：README から試せて、コードも見られる（対象：SC-5）

採用担当者として、README から公開版を開き、そのコードも読みたい。なぜなら、動くものとコードの両方を見て、技術力を判断したいから。

- AC-11：README の上のほうに、公開の URL が載っている
- AC-12：GitHub のリポジトリが公開されている。公開する前に、これまでの履歴に秘密情報（パスワード・API キー・個人のメールアドレスなど）がないことを確かめている

## S-6：公開先を選んだ理由が残っている（対象：SC-6）

開発者として、公開先を選んだ理由を残したい。なぜなら、あとで見直すときや、面接で説明するときに根拠が必要だから。

- AC-13：ADR-0003 に、公開先の候補の比較と選んだ理由、無料のプランの条件を公式の情報で確かめた日付が残っている

## 判断メモ

- Stories へのゲートでの判断：指摘なしで承認（SC にない AC-10「基本的なセキュリティの設定」も入れる）
