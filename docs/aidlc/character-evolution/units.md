# Units：キャラクターの成長（character-evolution）

## U-1：キャラクターのすがた（`src/features/evolution/`）

- 含む Story：S-1, S-2, S-3, S-4, S-5
- 依存：
  - `src/features/character/`（レベルの計算。段階はレベルから決める。ステータスとレベルアップのお知らせに、絵を組み込む）
  - `src/features/home/`（ホームの画面。吹き出しの絵と、すがたが変わったお知らせを出す）
  - `src/features/diary/`（日記の入力欄と、今日の日記の吹き出しの絵）
  - `src/features/history/`（後から書いたときのお知らせ、消す前の確認、案内の絵）
- 絵のファイル：`public/characters/`（5 枚の SVG）。ファビコン：`src/app/icon.svg`（Next.js の決まった置き場所）

段階の表（レベルの区切り・段階の名前・絵のファイル）と、絵を表示する部品は、どれも「キャラクターのすがた」の話なので、1 つの Unit にまとめる。ほかの画面は、この Unit の部品を呼び出す形で組み込む。

### Bolt 計画

- Bolt-1：段階の表と、絵を表示する部品。レベルから段階を求め、絵と読み上げ用の説明を出す。絵のファイルの中身を確かめて組み込む（AC-1 の段階の決め方, AC-4, AC-15）
- Bolt-2：画面に絵を組み込む。ステータスの絵と段階の名前、吹き出しの絵、名前を付ける前と案内の絵（AC-1〜AC-3, AC-5）
- Bolt-3：すがたが変わったお知らせと、レベルが下がったとき（AC-6〜AC-12）
- Bolt-4：ファビコン、スマホ幅での表示と、すがたの一連の操作の E2E テスト（AC-13, AC-14, AC-16）

### 設計（⑤で追記）

#### Bolt-1：段階の表と、絵を表示する部品

**ファイル**

```
src/features/evolution/stages.ts / .test.ts          # 段階の表と、レベルから段階を求める計算（画面に依存しない）
src/features/evolution/CharacterArt.tsx / .test.tsx  # 絵を表示する部品。大きさ・余白の切り取り・読み上げ用の説明
src/features/evolution/art-files.test.ts             # public/characters/ の SVG に、スクリプトや外部の読み込みがないことを確かめる
public/characters/stage-1.svg 〜 stage-5.svg         # 開発者の絵（④ で受け取り済み）
```

**段階の表（`stages.ts`）**

| 段階 | 始まるレベル | 名前         | 絵                        | 切り取る範囲（x, y, 一辺。400 × 400 の中） |
| ---- | ------------ | ------------ | ------------------------- | ------------------------------------------ |
| 1    | 1            | ねこだま     | `/characters/stage-1.svg` | 83, 132, 240                               |
| 2    | 5            | ころねこ     | `/characters/stage-2.svg` | 85, 126, 240                               |
| 3    | 10           | ちびねこ     | `/characters/stage-3.svg` | 71, 90, 270                                |
| 4    | 15           | えらそうねこ | `/characters/stage-4.svg` | 79, 56, 300                                |
| 5    | 20           | ねこ像       | `/characters/stage-5.svg` | 50, 56, 300                                |

- 切り取る範囲は、④ のモック（画面 2b）で、どの段階もはみ出さないことを確かめた値
- 段階の名前・レベルの区切り・絵のファイル・切り取る範囲は、この表 1 か所にまとめる（あとで絵や区切りを変えるときは、ここだけを直す）

| 関数                                   | 中身                                                                                      |
| -------------------------------------- | ----------------------------------------------------------------------------------------- |
| `getStage(level)`                      | そのレベルの段階（表の 1 行）。レベル 20 以上は段階 5（AC-1）                             |
| `stageChange(levelBefore, levelAfter)` | 段階が上がったか（`"up"`）、下がったか（`"down"`）、変わらないか（`null`）。Bolt-3 で使う |

**絵を表示する部品（`CharacterArt`）**

- 受け取るもの：段階、表示する大きさ（画素）、余白を切り取るか、読み上げ用の説明（なければ飾りとして扱う）
- 絵は `<img>` で表示する。SVG を画像として読み込むので、ファイルの中のプログラムは動かない（AC-15）
  - Next.js の `next/image` は使わない。SVG は画像の圧縮をしても小さくならず、`next/image` で SVG を扱うには追加の設定がいる。ESLint の「`<img>` より `next/image` を使う」という注意は、理由を書いたうえでこの部品だけ外す
- 余白を切り取るときは、決めた大きさの枠（はみ出しを隠す）の中で、表の範囲が枠いっぱいになるように、絵を拡大して位置をずらす（モックと同じ計算）
- 読み上げ用の説明があるときは `alt` に入れる（例：「ぴよ のすがた（ころねこ）」）。ないときは `alt=""` にして、読み上げない（AC-4）

**絵のファイルの見張り（`art-files.test.ts`）**

- `public/characters/` の 5 枚を読み、次のものが入っていないことを確かめる：`<script`、`on〜=`（動きの指定）、`href`、`<image`、`<foreignObject`、`url(`、`@import`、`<text`（文字が図形になっているか）
- 絵を差し替えたときに、うっかり危ないものや文字が入っても、テストで気づけるようにする（AC-15）

**⑥ で書くテスト（例）**

- `getStage`：レベル 1・4 → 段階 1、5・9 → 2、10・14 → 3、15・19 → 4、20・35 → 5。名前と絵のファイルが表のとおり（AC-1）
- `stageChange`：4 → 5 は上がる、5 → 6 は変わらない、3 → 6（一度に 2 つ以上）は上がる、5 → 4 は下がる
- `CharacterArt`：説明があれば読み上げで「ぴよ のすがた（ころねこ）」と読める／なければ読み上げない（AC-4）／切り取るときは枠が指定の大きさで、中の絵が表の範囲に合わせて拡大される
- `art-files`：5 枚とも存在し、上のものが入っていない（AC-15）

**ADR**

新しい技術の選定はないため、ADR は作らない（`<img>` を使う判断は、この units.md に記録する）。

#### Bolt-2：画面に絵を組み込む

**🐣 を置き換える場所**（今のアプリで 🐣 を使っている 8 か所）

| 場所                                                       | 置き換える絵 | 大きさ・切り取り    | 読み上げ                            | 対象の AC |
| ---------------------------------------------------------- | ------------ | ------------------- | ----------------------------------- | --------- |

| 今日の日記の入力欄の吹き出し（`DiaryEditor`）              | 今の段階     | 48px・切り取る      | 読み上げない（飾り）                | AC-2      |

| 名前の入力と確認（`NameForm`、2 か所）                     | 段階 1       | 220px・切り取らない | 読み上げない                        | AC-3      |
| 振り返りの「ホームで名前を付けてね」（`HistoryPage`）      | 段階 1       | 160px・切り取らない | 読み上げない                        | AC-3      |

- 最後の 2 か所は、AC にない場所。「まだ日記がないよ」はキャラクターがいるので今の段階、「データを読み込めなかった」はキャラクターがわからないので段階 1 にする。⑧ で「仕様にない実装」として確認する

**段階の渡し方**

- `CharacterStatus` は、受け取ったキャラクターの経験値からレベルと段階を求める（キャラクターの部品が、すがたの部品を呼び出す。すがたの部品はキャラクターの部品を呼ばないので、呼び合いにはならない）
- 吹き出しの部品（`DiaryEditor`・`TodayEntry`・`EntryForm`）は、段階を受け取る（`stage`）。ホームと振り返りのページが、キャラクターの経験値から段階を求めて渡す。振り返りでは `HistoryList` を通して `EntryForm` まで渡す
- 名前の入力・壊れたデータのお知らせ・キャラクターのいない案内は、段階 1（表の最初の行）を使う
- 開き直したときも、保存されている経験値から同じ段階になる（AC-5。新しく保存するものはない）

**ステータスとホームのレイアウト**（モックの判断どおり）

- ステータスの名前の横に、段階の名前を小さな枠で出す（例：「ぴよ」「ころねこ」）
- ステータスの区画の上下の余白を 16px から 12px に詰める
- 今日の日記の入力欄の高さを 160px から 200px に広げる

**⑥ で書くテスト（例）**

- `CharacterStatus`：経験値 179（Lv. 4）は「ねこだま」、180（Lv. 5）は「ころねこ」の絵と名前。絵の説明「ぴよ のすがた（ころねこ）」（AC-1, 4）
- `DiaryEditor`・`TodayEntry`・`EntryForm`：渡された段階の絵が、飾りとして出る（AC-2）
- `NameForm`：入力と確認のどちらでも段階 1 の絵（AC-3）
- `HistoryPage`：キャラクターがいない案内は段階 1、日記がない案内は今の段階（AC-3）。後から書く入力欄の吹き出しは今の段階（AC-2）
- `BrokenDataNotice`：段階 1 の絵
- `Home`：開き直しても、保存されている経験値に合った段階の絵と名前が出る（AC-5）／吹き出しの絵も同じ段階（AC-2）

#### Bolt-3：すがたが変わったお知らせと、レベルが下がったとき

**ファイル**

```
src/features/character/LevelUpDialog.tsx / .test.tsx  # すがたが変わったときの見た目（evolvedTo）を加える
src/features/home/Home.tsx / .test.tsx                # 今日の日記でレベルが上がったとき、段階が変わったかを調べて渡す
src/features/history/HistoryPage.tsx / .test.tsx      # 後から書いてレベルが上がったときも同じ
src/features/history/DeleteDialog.tsx / .test.tsx     # 消すと前の段階に戻るときだけ「すがたも前にもどるよ。」を出す
```

**すがたが変わったお知らせ（AC-6〜AC-10）**

- 新しい部品は作らず、今のレベルアップのお知らせ（`LevelUpDialog`）に「新しい段階」（`evolvedTo`）を渡せるようにする。開き方・「とじる」へのフォーカス・Esc キーで閉じるしくみは、今のものをそのまま使う（AC-10）
- `evolvedTo` があるとき：🎉 の代わりに新しい段階の絵（240px、切り取らない）、「<名前> が <段階の名前> になった！」「レベル N になったよ」「とじる」
- `evolvedTo` がないとき：これまでどおり「🎉」「<名前> が レベル N になった！」「これからもよろしくね」（AC-7）
- 絵は、すぐ下の文で同じことを伝えるので、飾りとして読み上げない。お知らせの名前（見出し）は「<名前> が <段階の名前> になった！」

**段階が変わったかの調べ方**

- ホーム（今日の日記）と振り返り（後から書く）で、保存する前のレベルと、経験値を足したあとのレベルを比べ、`stageChange` が「上がった」なら `evolvedTo` に新しい段階を渡す（AC-6, AC-8）
- 一度に 2 つ以上レベルが上がっても、比べるのは前と後の段階なので、同じように知らせる（AC-9）
  - 今の経験値のきまりでは、1 回に入る経験値は最大 60（日記 10 + ボーナス 50）。レベル 4 以上では 1 回で 1 つしか上がらないため、実際に段階をまたいで 2 つ上がることは起きない。`stageChange` の単体テスト（Bolt-1 で作成済み）で確かめる
- お知らせの状態は、「上がったレベル」だけから「上がったレベルと、変わった段階（あれば）」に広げる

**レベルが下がったとき（AC-11, AC-12）**

- ステータスの絵は経験値から毎回決まるので、消して下がれば、そのまま前の段階の絵になる（AC-11。Bolt-2 の作りで足りる）
- 消す前の確認（`DeleteDialog`）は、すでに受け取っている「消す前のレベル」と「消したあとのレベル」で `stageChange` を調べ、「下がった」ときだけ、レベルが下がる文の下に「すがたも前にもどるよ。」を注意の色で出す（AC-12）

**⑥ で書くテスト（例）**

- `LevelUpDialog`：`evolvedTo` があれば、段階の絵と「ぴよ が ころねこ になった！」「レベル 5 になったよ」が出て、🎉 は出ない（AC-6）／なければ、これまでどおり（AC-7）
- `DeleteDialog`：レベル 5 → 4 なら「すがたも前にもどるよ。」が出る／6 → 5 なら出ない（AC-12）
- `Home`：経験値 170（Lv. 4）で今日の日記を書くと 180（Lv. 5）になり、すがたが変わったお知らせが出る（AC-6）／経験値 20 → 30（Lv. 1 → 2）は、いつものお知らせ（AC-7）
- `HistoryPage`：経験値 175 で後から書くと 180 になり、すがたが変わったお知らせが出る（AC-8）／経験値 180 で日記を消すと 170（Lv. 4）になり、確認に「すがたも前にもどるよ。」が出て、ホームのステータスがねこだまに戻る（AC-11, AC-12）

**ADR**

この Bolt でも ADR は作らない。

## PR の単位

Bolt は 4 つで、`streak`（Bolt 4 つ・1 PR）と同じくらいの大きさ。ルールどおり、1 ブランチ・1 PR（`feat/character-evolution`）で進める。

## ④ UI モックについて

ステータス・吹き出し・すがたが変わったお知らせ・消す前の確認の見た目が変わる。開発者の 5 枚の絵と段階の名前を使って、`diary-history`・`streak` と同じく HTML のモックを作ることを提案する。そのため、④ に入る前に、絵の SVG と段階の名前を受け取る。

- Units へのゲートでの判断：指摘なしで承認（1 ブランチ・1 PR のまま。④ UI モックは開発者の絵を使って HTML で作る）
