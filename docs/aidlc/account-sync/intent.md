# Intent：ログインとクラウド保存（account-sync）

日記を続けたい人が、Google アカウントでログインするだけで、育てたキャラクターと日記をスマホでも PC でも同じように見て書き続けられ、しかもその日記は本人にしか読めない、と安心して預けられるようにする。

## 対象ユーザー

- 毎日日記を書きたいが、書くのを続けられない人（`diary-exp` と同じ）
- スマホと PC など、複数の端末やブラウザで日記を書きたい人
- 機種変更やブラウザのデータの消去で、育てたキャラクターと日記を失いたくない人
- ログインせずにまず試したい人（採用担当者を含む）。この人たちには、これまでどおりログインなしで使える状態を残す

## SC（成功条件）

- SC-1：ログインしなくても、これまでどおりブラウザの中に保存して、すべての機能（名付け・日記・振り返り・連続記録・成長）が使える
- SC-2：Google アカウントでログインでき、ログインしていることと、どのアカウントでログインしているかが画面でわかる
- SC-3：ログイン中に書いた日記と、キャラクターの名前・経験値はクラウドに保存される。別の端末やブラウザで同じアカウントにログインすると、同じキャラクターと日記が見られ、続きを書ける
- SC-4：初めてログインしたとき、アカウントにデータがなければ、ブラウザの中のキャラクターと日記がそのままアカウントに移る。レベル・経験値・連続日数・ボーナス・すがたは移す前と変わらない
- SC-5：ブラウザとアカウントの両方にデータがあるときは、それぞれのキャラクターの名前・レベル・日記の件数を見比べて、どちらを使うか選べる。選ばなかった方は、確認のうえで消える（2 つを混ぜない）
- SC-6：クラウドの日記とキャラクターは、ログインした本人しか読み書きできない。ほかのアカウントや、ログインしていない人からは読めない
- SC-7：ログアウトでき、ログアウトしたあとは、その端末に日記もキャラクターも残らない
- SC-8：退会でき、退会すると logling のアカウントと、クラウドの日記・キャラクターがすべて消える。消す前に、何が消えるか（Google アカウントそのものは消えないことも）がわかる確認が出る
- SC-9：ログイン中に通信できず保存できなかったときは、保存できなかったことがわかり、書いた文は消えずに残る（もう一度保存を試せる）
- SC-10：どんなデータを、どこに保存し、誰が読めて、どうすれば消せるかを説明するページがあり、ログインの前に読める
- SC-11：スマホの画面幅（375px）で、横スクロールなしにログイン・引き継ぎ・ログアウト・退会ができる

## 前提

- DB と認証の仕組みは、⑤ で公式の情報を比べて ADR で決める（候補は Supabase。CLAUDE.md の推奨）。無料で使える条件（しばらく使われないと止まるかなど）も、そのときに確かめる
- Google ログインを一般の人に公開するための条件（Google 側の同意画面の設定、説明ページの URL など）は、⑤ で公式の情報を確かめる
- 1 つのアカウントに、キャラクターは 1 体（今と同じ）
- 日付の区切り（朝 4 時、端末の時刻）、経験値・連続記録・ボーナス・すがたのきまりは変えない
- ログイン中のデータの置き場所はクラウドにする。ログアウトしたときに端末に残さないため、ブラウザの中には残さない
- ブラウザの中のデータをアカウントに移したら、ブラウザの中のデータは消す（ログアウトしたあとに古いデータが出てこないようにするため）
- ログアウトしたあとは、ログインしていない状態（名前を付けるところ）から始まる
- 退会で消すのは logling の側（アカウントの登録、日記、キャラクター）だけ。Google アカウントそのものと、Google の設定画面に残る「logling へのログインを許可した」記録には触れない。その記録の消し方は説明ページに書く。退会したあとに同じ Google アカウントでログインすると、空の新しいアカウントとして始まる
- これまでの機能の「データはブラウザの中だけに保存され、外部に送られない」（`diary-exp` の AC-17 など）は、ログインしていないときの約束として残す。ログインしたときは、本人だけが読めるクラウドに保存する、という形で ⑧ の要件定義書に書き足す

## スコープ外

| 内容                                                     | 扱い                                                                                                                  |
| -------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| 通信できないときに書いた日記を端末にためて、あとで送る   | 新しい機能 `offline-write` に分ける（ロードマップに追加）。この機能では、保存できなかったことがわかり文が消えないまで |
| メールでのログイン（メールのリンク、メールとパスワード） | 必要になったら検討。メール送信サービスと、自分のドメインが必要になるため                                              |
| 日記の暗号化（開発者も DB の中身を読めない形）           | 扱わない。説明のページで、誰が読める可能性があるかを正直に書く                                                        |
| 複数のキャラクター、アカウントの切り替え                 | 扱わない                                                                                                              |
| データの書き出し（ファイルに保存）                       | 必要になったら検討                                                                                                    |
| 両方のデータを日付ごとに混ぜて 1 つにする                | 扱わない（同じ日が両方にあるときや、キャラクターが 2 体あるときの扱いが複雑になるため）                               |

## 判断メモ

- 作成前に確認した点：ログインは任意（ログインなしでも使える）／ログインは Google アカウント／初めてのログインではブラウザのデータを移し、両方にあればどちらかを選ぶ／ログアウトと退会を含める
- 却下した案：メールでのログインは、Supabase の最初から付いているメールの仕組みが「1 時間に 2 通まで・チームの一員のアドレスだけ・本番向けではない」ため、別のメール送信サービスと自分のドメインが要るとわかり、採らなかった
- ゲートで確認した点：退会は Google との連携を切ることかを確かめ、logling の側のアカウントとデータを消すことだと SC-8 と前提に書き足した
- Intent へのゲートでの判断：上記を反映して承認（ログアウトで端末に何も残さない、移したらブラウザ側は消す、暗号化はしない、説明ページを作る、もこのまま）
- 分けた点：「通信できないときも書ける」は、端末にためた変更をあとで送る仕組みと、別の端末とぶつかったときの扱いが要り大きいため、`offline-write` として別の機能にした
