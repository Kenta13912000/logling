# Units：下のタブで画面を切り替える（tab-navigation）

## U-1：画面の移り方（`src/features/navigation/`）

- 含む Story：S-1〜S-8（すべて）
- 依存：
  - `src/app/`（すべてのページに、同じ上の帯と下のタブを出す）
  - `src/features/home/`・`src/features/history/`・`src/features/account/`・`src/features/privacy/`（それぞれの上の帯のリンクをなくす。お知らせや確認の窓の位置を、タブにかぶらないように直す）

下のタブ、「その他」の画面、設定の画面は、どれも「画面をどう移るか」の話なので、1 つのかたまりにまとめる。日記やログインの中身には触れない。

### Bolt 計画

- Bolt-1：下のタブ・「その他」の画面・設定の画面と、上の帯の整理。今いるタブの表示、名前を付ける前のタブ。これまでのテストの移り方の部分を直す（AC-1, AC-3〜AC-8, AC-12, AC-13）
- Bolt-2：文字を打っている間はタブを隠す。タブがページのいちばん下の内容やお知らせ・確認の窓にかぶらない。スマホの幅と、移り方の一連の操作の E2E テスト（AC-2, AC-9〜AC-11）

### 取り込みの依頼（PR）の分け方

- 1 つの PR（ブランチ `feat/tab-navigation`）にまとめる。2 回分の小さな機能のため
- DB は変えないので、取り込む前の本番の準備は要らない。取り込んだあとに、公開中のサイトで E2E テストを動かす

### 設計（⑤で追記）

#### Bolt-1：下のタブ・「その他」・設定と、上の帯の整理

**画面の組み立て**

- 上の帯と下のタブは、どのページにも同じものを出すので、ページごとではなく、**全ページ共通の枠**（`src/app/layout.tsx`）に置く。ページは、真ん中の中身だけを受け持つ
- 今は、ホーム・ふりかえり・アカウント・日記の保存のしかたが、それぞれ自分で外枠と上の帯（とリンク）を持っている。これをやめ、中身だけにする
- 上の帯の「logling」は見出しにしない（ページごとの見出しと重ならないように）。ホームには、読み上げ用の見えない見出し「ホーム」を置く（ほかのページは「ふりかえり」「アカウント」などの見出しがある）

```
<body>
  <div 外枠（幅 480px まで、真ん中寄せ）>
    <AppHeader />                 # 「logling」だけ
    <main 相当のページの中身 />    # 下のタブの高さの分、下に余白をとる
    <TabBar />                    # 画面の下に固定
  </div>
</body>
```

**今いるタブの決め方**（`tabs.ts`。画面に依存しない関数）

| ページ                                       | 今いるタブ |
| -------------------------------------------- | ---------- |
| `/`                                          | ホーム     |
| `/history`                                   | ふりかえる |
| `/more`・`/account`・`/privacy`・`/settings` | その他     |

- 今いるタブのリンクには `aria-current="page"` を付ける（読み上げ機能で「今のページ」と伝わる）
- タブのまとまりは `<nav aria-label="メインメニュー">`。アイコンは飾りとして読み上げない

#### Bolt-2：文字を打っている間・ほかのものにかぶらない・スマホの幅

**文字を打っている間はタブを隠す**（AC-9）

- 入力欄が選ばれたこと・離れたことを、ページ全体で聞く（`focusin`・`focusout`）。選ばれたのが文字を打つ欄（`textarea`、文字の `input`）なら、タブを隠す
- 隠すときは、画面から消すだけでなく、読み上げやキーボード操作の対象からも外す（`hidden`）
- 入力欄から別の入力欄に移ったときは、隠したまま。ボタンなど入力欄以外に移ったら、また出す
- チェックボックスやボタンが選ばれても隠さない
- 名前を付ける画面は、開いたときには入力欄が選ばれていないので、タブが出る（AC-12 と両立）

**ページのいちばん下がタブに隠れない**（AC-10）

- 全ページ共通の枠の下に、タブの高さ（56px）と iPhone の画面の下の線の分の余白をとる（Bolt-1 で入れた）
- iPhone の画面の下の線の分の長さをブラウザが教えてくれるように、ページの設定に `viewport-fit=cover` を足す（これがないと、その長さが 0 になる）

**お知らせ・確認の窓がタブに隠れない**（AC-11）

| もの                                   | 今                         | 直したあと                                                         |
| -------------------------------------- | -------------------------- | ------------------------------------------------------------------ |
| 経験値のお知らせ                       | 画面の上（上の帯のすぐ下） | そのまま。タブにはかぶらない                                       |
| 移したお知らせ（ログイン後の引き継ぎ） | 画面の下から 24px          | タブの上（タブから 16px 上）に上げる                               |
| 消す・レベルアップの確認の窓           | ブラウザの確認の窓の仕組み | そのまま。いつもいちばん手前に出て、後ろは押せない                 |
| 退会・引き継ぎ（どちらで続ける）の確認 | 画面全体を暗くする窓       | タブより手前に出す（重なりの順番を、タブより上にする）。タブも暗く |

## 判断メモ

- Units へのゲートでの判断：指摘なしで承認（1 つのかたまり、2 回、取り込みの依頼は 1 つ）
- Bolt-1 ⑤ へのゲートでの判断：指摘なしで承認（「logling」は見出しにせず、ホームに見えない見出し「ホーム」。名前を付ける前のテストは新しい仕様に書き直す。ふりかえりの「ホームへ」ボタンは残す）
- Bolt-1 ⑥ へのゲートでの判断：指摘なしで承認（前の機能の移り方のテストは、前の機能の AC の番号を名前に残してタブと「その他」のテストへ移す。前の機能の要件定義書は ⑧ で直す）
- Bolt-1 ⑦ の作成中に変えた点：diary-exp AC-1 の単体テストが、ホームの中の見出し「logling」を確かめていた（⑥ で見落とし）。アプリ名は共通の上の帯に移って見出しにしないため、名前の入力欄だけを確かめる形に直した
- Bolt-1 ⑦ へのゲートでの判断：指摘なしで承認（確認の窓が下のタブより手前に出ないこと、引き継ぎのお知らせがタブに重なることは、Bolt-2 の AC-11 で直す）
- Bolt-2 ⑤ へのゲートでの判断：指摘なしで承認（経験値のお知らせは、見本の説明と違い実際は画面の上に出ていてタブにかぶらないため、今の位置のまま。入力欄が選ばれている間はタブを押せない。`viewport-fit=cover` を足す）
- Bolt-2 ⑥ へのゲートでの判断：指摘なしで承認（そのままにするところ（AC-2、消す・レベルアップの確認の窓）のテストは最初から通る。E2E で、タブの上の線 1px の分だけフッターがタブに重なるのを見つけたので、⑦ で直す）
- Bolt-2 ⑦ の作成中に変えた点：
  - ボタンを押し始めた瞬間に入力欄から選択が移ってタブが出ると、画面のいちばん下のボタンにタブがかぶり、押せなかった（E2E で見つけた）。押している途中は、押し終わってからタブを出す形にした
  - 開発中のサーバーでは準備の処理が 2 回動くため、名前を付ける画面の「最初は入力欄を選ばない」しかけが効かず、開いた時点でタブが隠れていた。前と比べて段階が変わったときだけ入力欄を選ぶ形に直した
- Bolt-2 ⑦ へのゲートでの判断：指摘なしで承認（上の 2 つの直しと、それを確かめる単体テスト 2 件の追加）
