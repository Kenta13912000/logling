# Intent：下のタブで画面を切り替える（tab-navigation）

スマホで日記を書く人が、どの画面にいても、親指の届く画面の下のタブで、ホーム・ふりかえり・その他（アカウント、日記の保存のしかた、設定）に迷わず移れるようにする。

## 対象ユーザー

- 毎日日記を書きたいが、書くのを続けられない人（`diary-exp` と同じ）。主にスマホで使う
- ログインや説明ページなど、画面が増えてきたことで、どこから行けばよいか迷う人

## SC（成功条件）

- SC-1：どの画面（ホーム・ふりかえり・その他・アカウント・日記の保存のしかた・設定）でも、画面の下に「ホーム」「ふりかえる」「その他」のタブがあり、1 回押すとその画面に移れる
- SC-2：今どのタブの中にいるかが、見た目と読み上げ機能の両方でわかる。アカウント・日記の保存のしかた・設定は、「その他」の中にいる扱いにする
- SC-3：「その他」の画面から、アカウント（ログイン・ログアウト・退会）、日記の保存のしかた、設定に行ける。設定は入口だけで、開くと「これから増えるよ」とわかる
- SC-4：上の帯は「logling」だけになり、画面を移るためのリンクは下のタブにまとまる
- SC-5：スマホで文字を打っている間（日記・名前・振り返りの入力欄）はタブが隠れ、入力欄やキーボードにかぶらない。打ち終わると、また出る
- SC-6：タブが、ページのいちばん下の内容（ボタン、ホームのフッターなど）や、iPhone の画面の下の線にかぶらない
- SC-7：名前を付ける前も、タブで移れる（ふりかえりは、今と同じく「ホームで名前を付けてね」と出る）
- SC-8：これまでの機能の動き（日記・振り返り・連続記録・成長・ログイン・引き継ぎ・退会）は変わらない
- SC-9：幅 375px で横スクロールが出ず、タブは押しやすい大きさ（高さ 44px 以上）

## 前提

- 「その他」は新しいページ（`/more`）にする。アカウント（`/account`）と日記の保存のしかた（`/privacy`）は今のページのまま、「その他」から開く
- 設定（`/settings`）は、入口と「これから増えるよ」だけのページ。中身は、必要になった機能で足す（たとえば `pwa-reminder` の通知の時刻）
- 名前を付ける前の画面の「ほかの端末で使っていた人は ログイン ›」は残す（新しい端末でログインする人のため）
- ホームのいちばん下のフッター（アプリの説明と「日記の保存のしかた」）は残す。Google ログインの公開で、ホームページにアプリの説明と説明ページへのリンクが求められるため
- 保存の仕方や DB は変えない。本番の DB の準備は要らない
- スマホを優先する。PC でも同じ下のタブを使う

## スコープ外

| 内容                                     | 扱い                                                |
| ---------------------------------------- | --------------------------------------------------- |
| 設定の中身                               | 必要になった機能で足す（`pwa-reminder` の通知など） |
| カレンダーのタブ                         | `calendar` を作るときに、タブを増やすかを考える     |
| タブの並べ替え・タブの数を利用者が変える | 扱わない                                            |
| PC 向けの横のメニュー                    | 扱わない（PC でも下のタブ）                         |
| 画面を移るときの動き（アニメーション）   | 扱わない                                            |

## 判断メモ

- 作成前に確認した点：タブは「ホーム」「ふりかえる」「その他」の 3 つにし、「その他」にアカウント・日記の保存のしかた・設定をまとめる（開発者の案。アカウントを直接タブにする案より、あとから増えても数が変わらない）／上の帯のリンクはなくして「logling」だけにする／文字を打っている間はタブを隠す／説明ページにもタブを出す／設定は入口だけ置く／ホームのフッターは残す
- ゲートで確認した点：開発者のイメージは LINE の下のタブ（アイコンと短い名前、今いるタブだけ色が変わる）。形の考え方は同じにし、色やアイコンは logling に合わせて作る（ほかのアプリの見た目はまねない）。細かい見た目は ④ の画面の見本で決める
- Intent へのゲートでの判断：上記を確かめたうえで承認
