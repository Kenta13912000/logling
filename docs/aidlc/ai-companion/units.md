## テストの方針

- 単体テストと E2E テストでは、AI のサービスに本当には頼まない。サーバーの処理の中の「AI に頼む部品」を、決まった文を返す偽物に差しかえる（費用がかからず、毎回同じ結果になる）
- E2E テスト用の開発サーバー（テスト用のログインのとき）は、鍵を持たず、偽物のコメントを返す
- コメントの中身の決まり（AC-7・AC-8）は、毎回の答えが変わるため、ふつうのテストでは確かめられない。日記の見本（ふつうの日・つらい日・指示が紛れた日など）を本物の AI に頼んで、決まりを守っているかを確かめる手元の確かめを用意し、⑦ で開発者の承認を得てから 1 回動かす（数円）

## 取り込みの依頼（PR）の分け方

- 1 つの PR（ブランチ `feat/ai-companion`）にまとめる。「設定」でオンにできても、コメントが出なければ意味がないため、5 回分をまとめて出す
- 取り込む前の本番の準備：Neon の `main` に表を作る、Anthropic の API の鍵を作って Vercel の Production（Secret）に入れる、Anthropic の管理画面で 1 か月の上限を設定する（`pwa-reminder` と同じ手順。開発者と一緒に行う）
- 取り込んだあと：公開中のサイトで E2E テストを動かし、開発者の iPhone でオンにして、日記にコメントが付くことを確かめる

#### Bolt-1：オン・オフと、日記ごとのコメントの表

**表**（`src/lib/db/schema.ts`。`npm run db:generate` で SQL を作る）

`companion_settings`（1 人 1 行。オンにしたことがない人は行がない＝オフ）

| 列           | 型                    | 中身                                                                                                                              |
| ------------ | --------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `user_id`    | text（主キー）        | 持ち主。`user` を消すと一緒に消える（退会）                                                                                       |
| `enabled`    | boolean               | オンかどうか                                                                                                                      |
| `enabled_at` | timestamp（なしも可） | 最後にオンにした時刻（確認の窓で「オンにする」を押した時刻）。Bolt-2 で、この時刻より前に書いた日記にはコメントを作らない（AC-9） |
| `updated_at` | timestamp             |                                                                                                                                   |

`diary_comments`（日記 1 件にコメント 1 つ）

| 列                | 型        | 中身                                                                                                                                                       |
| ----------------- | --------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `user_id`・`date` | 主キー    | `diary_entries` の（`user_id`・`date`）を指す。日記を消すと一緒に消える（AC-12）。退会や引き継ぎの選び直しでキャラクターを消したときも、日記と一緒に消える |
| `body`            | text      | コメント（200 文字まで。DB の決まりでも確かめる）                                                                                                          |
| `created_at`      | timestamp |                                                                                                                                                            |

- 日記を書き直しても、コメントの行には触れない（AC-11）

**読み出し**（`src/features/cloud/repository.ts` の `getSaveData`）

- 保管場所から読むときは、日記に `diary_comments` をつなげ、コメントのある日記に `comment` を付ける（`DiaryEntry` に、なくてもよい `comment?: string` を足す）
- ブラウザの中のデータには、これまでどおり `comment` は入らない。引き継ぎ（ブラウザ → アカウント）のときも `comment` は受け取らない（`parseEntry` は今のまま、知らない項目を落とす）
- これで、ホームと振り返りは今の読み出しのまま、コメントも受け取れる（ほかの端末でも同じ：AC-10）

**サーバーの処理**（`src/features/companion/actions.ts`。`"use server"`。持ち主はログイン情報から決める）

| 処理                           | 中身                                                                                                     | 結果                                                     |
| ------------------------------ | -------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| `getCompanionSetting()`        | この人がオンかどうか                                                                                     | オン／オフ／ログインしていない／失敗                     |
| `setCompanionEnabled(enabled)` | オン・オフを保存する。オンにするときは `enabled_at` を今にする。オフでは行を残し、`enabled` だけを変える | 保存したあとの状態／ログインしていない／正しくない／失敗 |

- `enabled` が true / false 以外なら「正しくない」
- オフにしても、これまでのコメントは消さない（AC-3）

**テスト**

| テスト                                                                                                  | 種類 | AC         |
| ------------------------------------------------------------------------------------------------------- | ---- | ---------- |
| オンにしたことがない人はオフ。オンにすると `enabled_at` が入り、オフにすると `enabled` だけが変わる     | 単体 | AC-1〜AC-3 |
| ほかの人のオン・オフは読めず、変えられない。ログインしていないと、読む・変えるのどちらもできない        | 単体 | AC-4       |
| true / false 以外は保存しない。DB で失敗したときは「失敗」を返す                                        | 単体 | AC-4       |
| コメントのある日記は、読み出すと `comment` が付く。ない日記には付かない。ほかの人のコメントは出ない     | 単体 | AC-10      |
| 日記を書き直しても、コメントはそのまま                                                                  | 単体 | AC-11      |
| 日記を消すと、その日記のコメントも消える。退会（`user` を消す）と、すべてのコメントとオン・オフが消える | 単体 | AC-12      |
| 200 文字を超えるコメントは保存できない（DB の決まり）                                                   | 単体 | AC-7       |

## 判断メモ

- Bolt-1 ⑥ へのゲートでの判断：指摘なしで承認（コメントを読むテストは、設計の `cloud/repository.test.ts` ではなく、コメントを残す処理と一緒に `companion/repository.test.ts` にまとめた）
- Bolt-1 ⑦ へのゲートでの判断：指摘なしで承認（表を作る SQL は `drizzle/0002_companion.sql`。開発用の DB（`dev`）に当てた。本番は取り込む前の準備で当てる。DB の 200 文字の決まりは絵文字を多めに数えるため、Bolt-2 でアプリの側で十分短く切る）
