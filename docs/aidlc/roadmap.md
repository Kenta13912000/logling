# ロードマップ

| 順番 | 機能（feature 名）    | 概要                                                                                                   | 優先度   | 状態   |
| ---- | --------------------- | ------------------------------------------------------------------------------------------------------ | -------- | ------ |
| 1    | `diary-exp`           | 日記を書くとキャラに経験値が入り、レベルが上がる。データはブラウザ内に保存する                         | MVP      | 未着手 |
| 2    | `release`             | Vercel に公開し、誰でも触れる URL を用意する（デプロイ先を ADR で決める）                              | MVP      | 未着手 |
| 3    | `diary-history`       | 過去の日記を一覧で振り返る。編集・削除ができる                                                         | MVP      | 未着手 |
| 4    | `streak`              | 連続で書いた日数の表示とボーナス経験値。カレンダーで書いた日がわかる                                   | 次に作る | 未着手 |
| 5    | `character-evolution` | レベルに応じてキャラの見た目が変わる                                                                   | 次に作る | 未着手 |
| 6    | `account-sync`        | ログインとクラウド保存（DB・認証を ADR で決める。候補は Supabase）。ブラウザ内のデータを引き継ぐ       | 次に作る | 未着手 |
| 7    | `pwa-reminder`        | ホーム画面への追加（PWA）と、書き忘れを防ぐリマインド通知                                              | いつか   | 未着手 |
| 8    | `ai-companion`        | 日記の内容に合わせてキャラがコメントする（API の費用と、日記を外部に送るプライバシーの扱いを検討する） | いつか   | 未着手 |

## 前提

- **保存先**：MVP はブラウザ内（localStorage）に保存し、ログインなしで試せるようにする。ログインとクラウド保存は 6 で追加する
- **端末**：スマホ優先で画面を設計し、PC でも崩れないようにする

## 順番の理由

1. **`diary-exp`**：アプリの価値の核（書く → キャラが育つ）を最小の形で体験できる。ブラウザ内に保存するので、DB やログインを待たずに作れる。Next.js の初期画面もここで置き換える
2. **`release`**：早めに公開し、実際に触れる URL を README に載せる。以降は push や PR ごとに公開版で確認できる
3. **`diary-history`**：書いた日記を読み返せることは日記アプリの最低限の機能なので、MVP に含める
4. **`streak`・`character-evolution`**：「続けたくなる」仕組みを強める。1 で経験値とレベルの土台ができてから作る
5. **`account-sync`**：端末をまたいで使えるようにする。日記とキャラのデータ構造が 1〜5 で固まってから DB に移す
6. **`pwa-reminder`・`ai-companion`**：価値を広げるが、通知の許可、API の費用、日記を外部に送るプライバシーの検討が要るため後回しにする

## 判断メモ

- 作成前に確認した点：保存先は「最初はブラウザ内、後でログイン」／端末は「スマホ優先」／AI 機能は「いつか」に入れる
- ロードマップへのゲートでの判断：指摘なしで承認
