# 要件定義：ホーム画面に追加と、書き忘れを防ぐお知らせ（pwa-reminder）

実装（PR-1 は #18 で取り込み済み、PR-2 は `feat/pwa-reminder-push` の `13a9458` 時点）のコードとテストから書き起こした、この機能が実際に満たしている要件。計画との比較は [gap-report.md](../aidlc/pwa-reminder/gap-report.md) にある。技術の選定は [ADR-0007](../adr/0007-push-notifications.md)。

## 概要

logling をスマホのホーム画面に追加して、アプリのように開けるようにした（PR-1）。ログインしている人は、「設定」で「書き忘れのお知らせ」をオンにすると、選んだ時刻に、まだ日記を書いていない日だけお知らせが届く（PR-2）。お知らせは、オンにした端末にだけ届き、いつでもオフにできる。ログインしていない人のブラウザからは、これまでどおり何も外に送らない。

## ホーム画面に追加（U-1）

### アプリの名前・開き方（マニフェスト：`/manifest.webmanifest`）

| 項目                 | 値                                                     |
| -------------------- | ------------------------------------------------------ |
| 名前・短い名前       | logling                                                |
| 説明                 | 日記を書くとキャラクターが育つ、続けたくなる日記アプリ |
| 始まりのページ・範囲 | `/`                                                    |
| 開き方               | `standalone`（アドレス欄のない画面）                   |
| 背景の色・テーマの色 | `#fff8ec`（クリーム色）                                |
| 言語                 | `ja`                                                   |

- iPhone 向けに、ページの設定に「ホーム画面から開けるアプリ」であることと名前「logling」を入れる。テーマの色もクリーム色

### アイコン

| ファイル                             | 大きさ | 使い道                                   | 絵の大きさ                |
| ------------------------------------ | ------ | ---------------------------------------- | ------------------------- |
| `public/icons/icon-192.png`          | 192px  | ホーム画面（Android など）               | 80%（まわりはクリーム色） |
| `public/icons/icon-512.png`          | 512px  | ホーム画面・起動したときの画面           | 80%                       |
| `public/icons/icon-maskable-512.png` | 512px  | 丸や角丸に切り抜かれるとき（`maskable`） | 60%（真ん中の丸に収まる） |
| `src/app/apple-icon.png`             | 180px  | iPhone のホーム画面                      | 75%                       |
| `src/app/icon1.png`                  | 32px   | Safari などのファビコン（SVG と並べる）  | 絵だけ（まわりは透ける）  |

- どれも、段階 1 の絵のファビコン（`src/app/icon.svg`）から、スクリプト `npm run icons`（`scripts/make-icons.mjs`、部品 `sharp`）で作り、リポジトリに入れる。絵を描き直したら作り直す

### 画面の上下の余白

- ホーム画面から開くと、画面が時計や電池の表示の裏まで広がる。上の帯の上に、その分の余白（`env(safe-area-inset-top)`）をとる。ブラウザで開いているときは 0
- 下の余白は `tab-navigation` のまま

### 「設定」の「ホーム画面に追加」

- ブラウザで開いているとき：「ホーム画面に追加すると、アプリのように開けるよ」と、iPhone（Safari）・Android（Chrome）それぞれ 3 つの手順
- ホーム画面から開いているとき（開き方が `standalone`、または iPhone の `navigator.standalone`）：「✓ ホーム画面から開いているよ」だけ
- サーバーで画面を作るときは「ブラウザ」として出し、ブラウザで動き出したら見分け直す

## 書き忘れのお知らせ（U-2）

### 「設定」の「お知らせ」（「ホーム画面に追加」の上）

| 状態                                                | 出すもの                                                                                                                |
| --------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| ログインしているかを確かめている間                  | 切り替えは押せない                                                                                                      |
| ログインしていない                                  | 「ログインすると使えるよ。ログインする ›」（アカウントの画面へ）                                                        |
| 許可を断っている                                    | 「お知らせが許可されていないよ。端末の設定で、logling のお知らせを許可してね」                                          |
| 使える                                              | 切り替え「書き忘れのお知らせ」（はじめはオフ）。オンなら「時刻」と「この端末にだけ届くよ。15 分ほど遅れることがあるよ」 |
| しくみがなく、iPhone・iPad でブラウザから開いている | 「iPhone では、ホーム画面に追加して、そこから開くと使えるよ（追加のしかたは下にあるよ）」                               |
| しくみがない、またはお知らせの公開の鍵がない        | 「このブラウザでは、お知らせを使えないよ」                                                                              |

- 時刻は 0:00〜23:30 の 30 分ごとの 48 個から選ぶ。はじめは 21:00。オン・オフと時刻は端末ごと
- オンにする：押したときにだけブラウザの許可を求める → `/sw.js` を登録 → お知らせの登録 → 宛先・時刻・端末のタイムゾーンを保存。許可を断ったら「許可されていない」の文、答えずに閉じたらオフのまま。保存に失敗したら、ブラウザの登録をやめてオフのまま
- 時刻を変える：新しい時刻で保存。失敗したら前の時刻に戻す
- オフにする：サーバーの宛先を消してから、ブラウザの登録をやめる。失敗したらオンのまま
- 失敗したときは「⚠ 保存できなかった…通信できるところで、もう一度ためしてね」。保存している間は、切り替えと時刻を押せない

### お知らせを受け取るしくみ（`public/sw.js`）

- 登録するのは、お知らせをオンにしたときだけ。ページを見ただけでは登録しない
- 届いたら、題・文・ホーム画面と同じアイコン（192px）で出す。開く場所は、このサイトの中（`/` で始まり、`//` で始まらない）だけで、そうでなければ `/`。中身が読めなければ「logling」「今日の日記を書こう」
- 押すと、logling が開いていれば前に出してホームへ、開いていなければホームを開く
- ページを覚える処理（`fetch`）はない。新しい版を公開すれば、ホーム画面から開いても新しい版になる。`/sw.js` は毎回取り直す設定（`Cache-Control: no-cache, no-store, must-revalidate`）で配る

### 預かるもの（表 `push_subscriptions`）

| 列                         | 中身                                                    |
| -------------------------- | ------------------------------------------------------- |
| `endpoint`（主キー）       | お知らせのしくみのアドレス（端末とブラウザごと）        |
| `user_id`                  | 持ち主。`user` を消すと一緒に消える                     |
| `p256dh`・`auth`           | お知らせを暗号にするための、端末の鍵                    |
| `remind_minute`            | 0 時からの分（0〜1410、30 の倍数。DB の決まりでも守る） |
| `time_zone`                | オンにした端末のタイムゾーン                            |
| `last_sent_on`             | 最後に送った「その日」                                  |
| `created_at`・`updated_at` |                                                         |

- サーバーの処理 `getReminder`・`saveReminder`・`removeReminder`。持ち主は、ブラウザから送られた値ではなく、サーバーのログイン情報で決まる。ほかの人の宛先は読めず、消せない
- 受け取った値はすべて確かめる：宛先は `https` で、お知らせのしくみ（Google：`fcm.googleapis.com`・`android.googleapis.com`、Apple：`*.push.apple.com`、Mozilla：`*.push.services.mozilla.com`、Microsoft：`*.notify.windows.com`）のものだけ、2,000 文字まで。鍵は URL で使える Base64 の文字で決まった長さ。時刻は 30 分ごと。タイムゾーンはブラウザが知っている名前。余分な値は捨てる
- 同じ端末で別のアカウントがオンにすると、持ち主が付けかわり、「最後に送った日」も消える
- 失敗しても、宛先や鍵を記録（ログ）に出さない
- ログアウト：その前に、この端末の宛先を消し、ブラウザの登録もやめる（失敗してもログアウトする）。退会：すべての端末の宛先と時刻が消える

### 送る（`/api/reminders`）

- Vercel Schedules（試験提供）が 30 分ごと（`0,30 * * * *`）に `POST` で呼ぶ（`vercel.json`）。Hobby では毎回 0〜15 分ずれる
- 合言葉 `Authorization: Bearer <CRON_SECRET>` を、時間で差が出ない方法で比べる。違う・ない・サーバーの合言葉が 16 文字より短いときは `401` で何もしない。お知らせの鍵がなければ `503`
- 宛先ごとに、そのタイムゾーンで、選んだ時刻から 60 分のうちなら送る時刻とする（0 時をまたいでも数える）。「その日」（朝 4 時区切り）は、選んだ時刻の側で数える
- その日の日記をもう書いていれば送らない。「最後に送った日」がその日なら送らない。先に「最後に送った日」を書きかえられたときだけ送る（同じ回が 2 つ同時に動いても 1 回だけ）
- 送る中身：題「logling」、文「<キャラクターの名前>が待っているよ。今日の日記を書こう」（名前を付ける前は「今日の日記を書こう」）、開く場所 `/`。日記の本文は入れない。お知らせのしくみに預ける時間は 1 時間
- お知らせのしくみが `404`・`410` を返したら、その宛先を消す。そのほかの失敗では「最後に送った日」を戻し、次の回でもう一度ためす
- 記録に出すのは、送った数・書いていた数・消した数・失敗した数だけ

### 環境変数

| 名前                           | 中身                                     | 置き場所                                  |
| ------------------------------ | ---------------------------------------- | ----------------------------------------- |
| `NEXT_PUBLIC_VAPID_PUBLIC_KEY` | お知らせの公開の鍵（ブラウザにも渡す）   | Vercel の Production・手元の `.env.local` |
| `VAPID_PRIVATE_KEY`            | お知らせの秘密の鍵                       | 同上（Sensitive）                         |
| `CRON_SECRET`                  | `/api/reminders` の合言葉（16 文字以上） | 同上（Sensitive）                         |

- お知らせの鍵の連絡先は、GitHub の Issues のページ（個人のメールアドレスは使わない）
- PR ごとの確認用の公開には置かない（ログインがないので、お知らせも使えない）

### 説明ページ「日記の保存のしかた」の「お知らせ」（「ログアウトと退会」の後ろ）

> 「設定」で「書き忘れのお知らせ」をオンにした人（ログイン中の人）だけが使えます。
>
> オンにすると、この端末へのお知らせの宛先・選んだ時刻・タイムゾーンを預かり、まだ日記を書いていない日だけお知らせを送ります。
>
> お知らせは Apple や Google などのしくみを通って届きます。入るのはキャラクターの名前と決まった文だけで、日記の本文は入りません。
>
> 「設定」でオフにする・ログアウト・退会のどれかで、預かったものは消えます。
