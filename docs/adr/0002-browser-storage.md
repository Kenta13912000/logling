# ADR-0002：MVP のデータはブラウザの localStorage に保存する

- 日付：2026-10-29
- 状態：採用

## 背景

最初の機能 `diary-exp` では、キャラクター（名前・経験値の合計）と日記（1 日 1 件・最大 2000 文字）を保存し、ブラウザを開き直しても残っている必要がある（SC-5）。

ロードマップの前提で、MVP はログインなしですぐ試せるようにし、ログインとクラウド保存は `account-sync` で追加すると決めている。そのため、ここではサーバーや DB を使わず、ブラウザの中に保存する方法を選ぶ。

日記は個人的な内容なので、端末の外に送らないこと（AC-17）も重視する。

## 決定

ブラウザの **localStorage** に、キー `logling:v1` で 1 つの JSON（`version`・`character`・`entries`）として保存する。

- 形に `version` を持たせ、将来形を変えるときや `account-sync` でクラウドへ引き継ぐときの目印にする
- 読み込み時に形をチェックし、読めない場合は勝手に消さず、利用者が選んだときだけ控えのキーに移してやり直す（AC-21）
- 書き込みに失敗した場合（容量不足・保存の禁止など）は、その結果を画面に伝え、入力内容を残す（AC-22）

## 検討した他の案

| 案              | 採用しなかった理由                                                                                 |
| --------------- | -------------------------------------------------------------------------------------------------- |
| IndexedDB       | 容量が大きく非同期で扱えるが、API が複雑でラッパーのライブラリが必要になりやすい。MVP の量には過剰 |
| sessionStorage  | タブを閉じると消えるため、開き直しても残る（SC-5）を満たせない                                     |
| Cookie          | 容量が小さく（約 4KB）、通信のたびにサーバーへ送られる。日記を外に送らない方針（AC-17）に反する    |
| サーバー側の DB | 端末をまたいで使えるが、ログインと DB の選定が必要になる。`account-sync` で別の ADR として決める   |

## 結果・影響

- ログインなしで、すぐに日記を書いて試せる。日記は端末の外に出ない
- 容量はブラウザごとにおよそ 5MB。日記は 1 件最大 2000 文字なので、毎日上限まで書いても数年分は収まる見込み。容量不足は AC-22 の動きで扱う
- ブラウザのデータを消したり、別の端末・ブラウザで開いたりすると日記は引き継げない。この弱点は `account-sync` で対処する（intent.md の前提に記載済み）
- localStorage はブラウザでしか使えないため、サーバーでの描画時は「読み込み中」を出し、ブラウザで読み込んでから画面を出す

## 判断メモ

- 作成前に確認した点：保存データが読めないときは、お知らせを出し、選んだら控えを残してやり直す／保存に失敗したときは、メッセージを出し、書いた文章を残す
- ADR へのゲートでの判断：指摘なしで承認
