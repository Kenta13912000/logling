# ADR-0008：暗い色の画面は、色の決まりを端末の設定で切りかえて作る

- 日付：2026-11-14
- 状態：採用

## 背景

`settings` の U-2 で、端末が暗い色の設定（ダークモード）のときに、logling の画面も暗い色にする（[intent.md](../aidlc/settings/intent.md)・[stories.md](../aidlc/settings/stories.md) の S-4・S-5）。色を選ぶ項目は作らず、何も覚えない（SC-5）。明るい色のときは、今と同じ見た目にする（AC-11）。

今の画面は、色の決まり（`globals.css` の `@theme`：`cream`・`ink`・`ember` など）を使っているところと、色を直接書いているところ（`bg-white` や `#fde7d6` など）がまざっている。

## 決定

- **切りかえ方**：ブラウザが教えてくれる端末の設定（`prefers-color-scheme: dark`）だけで切りかえる。CSS の `@media` の中で、色の決まりの値（CSS の変数）を暗い色の値に置きかえる。JavaScript は使わないので、ページを開いた瞬間から正しい色で出て、端末の設定を変えるとそのまま切りかわる
- **色の決まりの名前**：今の名前（`cream`・`ink` など）はそのまま使い、暗い色では値だけを変える。名前を「背景」「文字」のような役割の名前に付けかえると、変更が画面全体に広がるため
- **新しく足す色の決まり**：色を直接書いていたところと、明るい色と暗い色で役割が分かれるところに足す

| 名前          | 使い道                           | 明るい色       | 暗い色          |
| ------------- | -------------------------------- | -------------- | --------------- |
| `surface`     | カード・帯・タブ・窓の地         | #ffffff        | #2a211b         |
| `link`        | リンク・今いるタブ               | #c2410c        | #fb8c4a         |
| `danger`      | 消す・退会のボタンの地           | #b42318        | #b42318（同じ） |
| `ember-soft`  | 案内の枠・今いるタブの塗り       | #fde7d6        | #4a2c1a         |
| `switch-off`  | 切りかえのオフの地               | #d8cbb8        | #5a4a3d         |
| `line-strong` | 時刻を選ぶ欄の枠                 | #d8c4a6        | #6b5a4a         |
| `ok`          | 「✓ ホーム画面から開いているよ」 | #3f6b2a        | #9ccc84         |
| `scrim`       | 確認の窓の後ろの幕               | 濃い茶色の 45% | 黒の 60%        |

- **ボタンの色**：「日記をのこす」などのオレンジのボタン（`ember`）と、消すボタン（`danger`）は、暗い色でも同じ色にする。白い文字との明るさの差（5.18・6.57）を保つため。文字として使うオレンジと赤は、暗い背景で読めるよう、`link` と `alert` を明るめにする
- **Google のログインのボタン**：Google の決まり（ブランドのガイドライン）にある暗い色のボタン（地 #131314・枠 #8e918f・文字 #e3e3e3）にする。ここだけは、色の決まりを増やさず、Tailwind の `dark:` で書く
- **ブラウザの部品**：`color-scheme: light dark` を付け、選ぶ欄の一覧やスクロールの帯なども、端末の設定に合わせた色にする
- **ブラウザの上の帯の色**：`viewport` の `themeColor` を、明るい色と暗い色の 2 つにする（`media` 付き）
- **守り方**：明るさの差と、色を直接書いていないことを、単体テストで確かめる（`globals.css` から色の値を読んで計算する）

## 検討した他の案

| 案                                                             | 採らなかった理由                                                                       |
| -------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| すべての部品に `dark:bg-…` を書き足す                          | 書き足す場所が多く、新しい部品で書き忘れやすい。色の値が画面のあちこちに散らばる       |
| JavaScript で端末の設定を読み、`<html>` に印を付けて切りかえる | 開いた瞬間に明るい色が一瞬出ることがある。色を選ぶ項目を作らないので、CSS だけで足りる |
| ダークモード用の部品（`next-themes` など）を入れる             | 色を選ぶ項目と、選んだ色を覚えるしくみのための部品で、今回は使わない。部品が増える     |

## 結果・影響

- これからの画面でも、色は色の決まりの名前で書く。`bg-white` や `#…` を直接書くと、単体テストで見つかる
- ホーム画面に追加したときの起動の画面の色（マニフェストの `background_color`・`theme_color`）は、明るい・暗いを分けられないため、クリーム色のまま
- 色を選ぶ項目を将来作るときは、`<html>` に印を付けるしくみを足し、`@media` と同じ値を印の中にも置く
