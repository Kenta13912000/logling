# 開発の記録：logling

日記を書くとキャラクターが育つ、続けたくなる日記アプリ「logling」を、AI（Claude Code）と組んで、要件定義から公開まで 3 週間で作った記録です。

- アプリ：https://logling.vercel.app（インストール不要。ログインしなくても使えます）
- リポジトリ：https://github.com/Kenta13912000/logling

## 何を作ったか

「毎日日記を書きたいけれど続かない」人のために、日記を書くたびにキャラクター（ねこ）に経験値が入り、レベルに応じてすがたが変わるアプリを作りました。

| #   | 機能                                 | 内容                                                                              |
| --- | ------------------------------------ | --------------------------------------------------------------------------------- |
| 1   | 日記で経験値                         | 1 日 1 件の日記で経験値が入り、レベルが上がる                                     |
| 2   | 公開                                 | Vercel に公開し、だれでも触れる URL を用意                                        |
| 3   | 日記の振り返り                       | 過去の日記の一覧。最近 7 日は書き直し・削除・後から書ける                         |
| 4   | 連続記録とボーナス                   | 続けて書いた日数と、区切りの日数でのボーナス経験値                                |
| 5   | キャラクターの成長                   | レベルに応じて 5 段階ですがたが変わる（絵は自分で描いたオリジナル）               |
| 6   | ログインとクラウド保存               | Google でログインすると、スマホでも PC でも続きが書ける（任意）。退会と説明ページ |
| 7   | 下のタブ                             | ホーム・ふりかえる・その他を、画面の下のタブで切り替える                          |
| 8   | ホーム画面に追加と書き忘れのお知らせ | アプリのように開け、まだ書いていない日だけ、選んだ時刻にお知らせが届く            |

技術：Next.js（App Router）・TypeScript・Tailwind CSS・Vitest・Playwright・GitHub Actions・Vercel・Neon（PostgreSQL）・Better Auth・Drizzle ORM・Web Push

## どう作ったか：AI-DLC

AI に任せきりにせず、「何のために・何を作るか」は私が決め、AI が案を作り、私が確かめて承認する進め方（AI-DLC）にしました。進め方の決まりは [CLAUDE.md](../CLAUDE.md) にあります。

1. **機能ごとに 8 つのステップ**：① 目的と成功条件 → ② ストーリーと受け入れ条件 → ③ 作る回の計画 → ④ 画面の見本 → ⑤ 設計 → ⑥ テストを書く → ⑦ 作る → ⑧ 実装から要件定義書を作り直し、計画との違いを確かめる
2. **ステップごとに私が承認**：AI は要約と「確認してほしい点」を出し、私が「承認・修正・止める」を選ぶまで次へ進みません。要約だけで決めず、必要に応じて、作られた文書・画面の見本・コードを自分で開いて確かめ、実際の画面や端末でも動きを確かめてから判断しています。判断の理由は、各文書の「判断メモ」に残しています
3. **技術の選び方は ADR に**：DB・認証・お知らせのしくみなどは、候補を比べて理由を [docs/adr/](adr/) に残しました
4. **公開後の確かめ**：機能を取り込むたびに、公開中のサイトで E2E テストを動かし、結果を記録しました

## 私が下した判断

**1. ログインは任意にした**
ログインとクラウド保存を作っている途中で、「そもそも日記アプリにログインは要るのか」と立ち止まりました。ログインしなくても、日記をブラウザの中だけに保存して使える形を残し、ログインは「ほかの端末でも続けたい人」のための選択肢にしました。「ログインしなければ、日記は外に送らない」という約束は、その後の機能でも守っています。

**2. 説明ページを、ふだんの言葉で書いた**
日記の保存のしかたを説明するページの案に「クラウド」「DB」といった言葉が並んでいたため、「一般の人にはわかりづらい」と指摘して書き直しました。「インターネット上の保管場所」のように言いかえ、専門の言葉を使っていないことをテストでも確かめています。

**3. 機能を小さく分けた**
作っている途中で出た案は、その機能に足さずに、別の機能としてロードマップに入れました。たとえば、下のタブはログインの機能から、カレンダーは連続記録から分けました。お知らせの機能も「ホーム画面に追加」と「お知らせ」の 2 つの PR に分け、先に出せる方から公開しました。1 回の変更を小さく保ち、確かめやすくするためです。

**4. お知らせは、ログイン中の人が自分でオンにしたときだけ**
お知らせは、その日の日記をまだ書いていない日だけ届くようにしたかったので、書いたかどうかがわかる「ログイン中の人」に限りました。こうすると、「ログインしなければ外に送らない」約束も守れます。はじめはオフで、いらない人には届きません。

## やり直すなら

- **ログインと保存先を早く決める**：ログインとクラウド保存を 6 番目に足したため、日記・振り返り・連続記録など、前に作った機能をたくさん直すことになりました
- **スマホ向けを早くする**：主にスマホで使うアプリなのに、下のタブやホーム画面に追加は後半になりました
- **AI との確認のやり方を先に決める**：確認の要約が画面に見えない、英語が混じるなどの行き違いが何度かありました。最初に確認の出し方を決めておけば、手戻りが減りました
- **初期構築をもっと手軽にしたい**：雛形・テストの基盤・CI・最初の ADR を、それぞれ確かめながら整えたので、最初の機能に入るまでに時間がかかりました
